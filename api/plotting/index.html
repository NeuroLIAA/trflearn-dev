    Plotting¶

    The shared plotting API. See the Plotting guide for usage.

    TRFPlots¶

    Every figure its owners share, plus the table of which one works where and the contract for adding a new one.

    The five mne.Evoked passthroughs carry MNE's own parameter list under Other Parameters, read from the installed MNE rather than copied — which is why this block is rendered by inspection.

    TRFPlots ¶

    Every shared figure, and the contract its owners implement.

    What you can draw, and where¶

    Six owners inherit this: a fitted model (models.TorchTRF), a cohort (group.TRFGroup), one stored subject reached as group("s01"), a cohort mixed model (mixed.TRFMixedModel, drawing its population kernel), a view of that mixed model -- lmm("s01") for a subject's own kernels, lmm.variability for the between-subject SD -- and the kernels a simulation injected (simulation.GroundTruth). Most figures work on all of them; the exceptions are worth knowing before reaching for one.

    Figure Model Cohort Subject Mixed Mixed view Truth Needs
    plot, plot_image, plot_psd ✓ ✓ ✓ ✓ ✓ ✓ —
    plot_joint, plot_psd_topomap ✓ ✓ ✓ ✓ ✓ ✓ montage
    plot_average ✓ ✓ ✓ ✓ ✓ ✓ —
    plot_contrast ✓ ✓ ✓ ✓ ✓ ✓ montage if kind="joint"
    plot_features, plot_feature ✓ ✓ ✓ ✓ ✓ ✓ montage
    plot_metric_topomap ✓ ✓ ✓ ✗ ✗ ✗ montage
    plot_source_butterfly, to_stc ✓ ✓ ✓ ✓ ✓ ✓ centroids
    plot_bootstrap ✗ ✓ ✗ ✗ ✗ ✗ —
    validation_plot ✓ ✗ ✗ ✗ ✗ ✗ —
    plot_subjects ✗ ✗ ✗ ✓ ✗ ✗ —
    plot_variance_components ✗ ✗ ✗ ✓ ✗ ✗ montage
    plot_fit_diagnostics ✗ ✗ ✗ ✓ ✗ ✗ montage

    "Needs a montage" means sensor positions, which arrive with an mne.Raw target or through core.TRFData.set_montage. Those figures draw topomaps, and without positions they raise saying so. The others need no channel info at all: on an owner fitted on arrays the channels are drawn as Target 0, Target 1 and so on. Source-space targets carry centroids instead, via core.TRFData.set_source_positions; they place the source figures, and no topomap.

    The green/red significance shading is cohort only. It comes from a statistic over subjects -- a cluster permutation test on a group, a Wald test on a mixed model -- and it is drawn by plot, plot_joint, plot_image, plot_average, plot_contrast, plot_features and plot_source_butterfly once that test has run. On every other owner show_stats=True is accepted and quietly does nothing -- the figure is the same as with show_stats=False. MixedPlots says what its shading means.

    Every ✗ is a plain AttributeError: plot_bootstrap needs per-subject distributions, validation_plot a grid search, plot_metric_topomap a held-out metric, and plot_subjects, plot_variance_components and plot_fit_diagnostics a fitted mixed model, so none exists on an owner that cannot have one -- a ground truth was never scored, so it has no metric either.

    Every figure returns its figure and accepts save_path (written, creating parent directories) and show; see _finalize_figure for what survives the close. Two settings, read by every figure of an object rather than passed per call: plot_baseline and plot_sphere, both below.

    Adding a figure¶

    Write it against the hooks, never against the owner's own attributes -- that is what keeps one method working for every owner. Take spec first, read the kernel through _baselined_kernel (not _plot_kernel, so the display baseline applies), end with _finalize_figure, and return what it returns. If the figure only makes sense for one owner, define it on that owner's subclass instead of here.

    Attributes:

    Name Type Description
    plot_baseline (tuple, dict or None)

    Display-only baseline; see the class body for the accepted forms.
    plot_sphere (tuple, float or None)

    Fixed head sphere for every topomap.

    plot_average ¶

    plot_average(
    spec: str | tuple,
    show_stats: bool = True,
    channel_reduce: str = "mean",
    x_units: str = "ms",
    title: str | None = None,
    sub_labels: list | None = None,
    alpha_level: float = 0.05,
    min_sig_channels: int | float = 1,
    color: str = "C0",
    style: str = "mne",
    save_path: str | PathLike | None = None,
    show: bool = False,
) -> Figure

    Butterfly and channel summary -- the figure that always works.

    A single axis for a scalar feature; for a multi-column one, two axes sharing the time axis: the kernel averaged over its sub-features on top, and a sub-features x time heatmap of the channel-collapsed coefficient below, with the non-significant cells attenuated.

    Parameters:

    Name Type Description Default
    spec str or tuple

    The feature to draw; a tuple names an interaction.

    		 required
    show_stats bool

    Shade the significant delay intervals green (positive) or red (negative) on the top axis. Cohort only: a model and a single subject have no cluster result, so this is accepted and does nothing there.

    		 True
    channel_reduce (mean, gfp)

    How the bottom panel collapses its channel axis -- not its sub-feature axis, which is what the rows are, and not the top panel, which always shows the sub-feature average. "mean" is the signed average, which keeps the polarity and is drawn on a diverging scale centred at zero. "gfp" is the RMS: reach for it when the response is dipolar, positive over some sensors and negative over others, where the signed mean cancels a real effect toward zero. It is non-negative, so it is drawn on a sequential scale and it discards the sign. No effect on a scalar feature, which has no such panel.

    		 "mean"
    x_units (ms, s)

    Unit of the time axis.

    		 "ms"
    title str or None

    Overrides the default, which is the subject id and the feature when there is a subject, else the feature alone.

    		 None
    sub_labels sequence or None

    Tick labels for the heatmap's sub-feature rows; must have one entry per sub-feature.

    		 None
    alpha_level float

    Significance cutoff applied to the p-value map.

    		 0.05
    min_sig_channels int or float

    Channels that must reach alpha_level for a delay to count. A float in (0, 1) is read as a fraction of them.

    		 1
    color str

    Colour of the native butterfly's channel-mean line.

    		 "C0"
    style (mne, native)

    How the top axis is drawn; see the Notes.

    		 "mne"
    save_path (str, PathLike or None)

    Where to write the figure; parent directories are created.

    		 None
    show bool

    Display the figure instead of closing it in pyplot.

    		 False

    Returns:

    Type Description
    Figure

    Raises:

    Type Description
    ValueError

    If style or channel_reduce is not one of its two values, or if sub_labels does not match the sub-feature count.
    Notes

    style="mne" draws the top axis with mne.Evoked.plot -- the same butterfly every other MNE figure uses, spatially coloured from the montage, with the GFP trace. What it plots is unchanged; only the rendering differs. It needs a montage, so without one it falls back to the native drawing: thin per-channel traces, a bold channel mean and a one-standard-deviation band. That fallback is why this figure is the one that always works. style="native" opts out and draws it that way regardless.

    The shading and the heatmap are drawn here in both styles; only the butterfly ever comes from MNE. The vertical axis and the colorbar are labelled in coefficient units, which under the default standardization are σ_target/σ_feature.

    plot_contrast ¶

    plot_contrast(
    spec_a: str | tuple,
    spec_b: str | tuple,
    kind: str = "average",
    *,
    show_stats: bool = True,
    channel_reduce: str = "mean",
    x_units: str = "ms",
    title: str | None = None,
    sub_labels: list | None = None,
    alpha_level: float = 0.05,
    min_sig_channels: int | float = 1,
    color: str = "C0",
    style: str = "mne",
    save_path: str | PathLike | None = None,
    show: bool = False,
    **kwargs: Any
) -> Figure

    Draw the difference between two features of one model.

    kind="average" (the default) gives the figure plot_average produces: a butterfly for a scalar feature, and for a multi-column one the sub-feature-averaged butterfly over a sub-features x time heatmap. It needs no montage, so it is the one that always works.

    kind="joint" gives the plot_joint figure instead -- MNE's butterfly with topographies at its peaks -- of the sub-feature-averaged difference. That is usually the figure a contrast is for: it answers "where and when do the two conditions diverge" in one panel. It needs a montage, and grid / mean / std / sem / ts_args / topomap_args may be passed through to it; channel_reduce and sub_labels do not apply to it.

    This is the picture behind TRFGroup.permutation_test_contrast_features / TRFGroup.tfce_contrast_features, and its reason to exist: those return a p-value for spec_a - spec_b while the difference itself was not drawable, so the effect could be tested and never looked at. With show_stats (the default) a stored result for this exact pair shades the butterfly green (spec_a above spec_b) or red (below), the same convention the test reports its sign in. Nothing is shaded when the pair has not been tested -- always the case for a single TRFModel, where cluster tests do not apply.

    Parameters:

    Name Type Description Default
    spec_a str or tuple

    The two features, both in the fitted model. The sign follows the subtraction. They must share a delay window and a sub-feature count; whether the difference means anything is the caller's to judge (see _resolve_contrast).

    		 required
    spec_b str or tuple

    The two features, both in the fitted model. The sign follows the subtraction. They must share a delay window and a sub-feature count; whether the difference means anything is the caller's to judge (see _resolve_contrast).

    		 required
    kind (average, joint)

    Which figure to draw, as above.

    		 "average"

    Returns:

    Type Description
    Figure

    Raises:

    Type Description
    ValueError

    If the two are the same feature, if their kernels disagree in shape or delay window, or if kind is not one of the two.
    RuntimeError

    If kind="joint" and the channels have no sensor positions.
    Notes

    x_units, title, style, color, alpha_level, min_sig_channels, save_path and show mean exactly what they mean in plot_average.

    Both kernels are partial coefficients from the same design and solve, so they share a λ, a normalization, the folds and the sample count, and each is estimated controlling for the other. Their difference therefore carries no trace of a difference in regularization -- which is exactly what subtracting two separately fitted models would give you. The canonical use is a pair of condition-coded versions of one regressor (attended vs unattended, target vs distractor) entered as two features.

    Butterfly of source regions, coloured by position, with a region map.

    The source-space counterpart of the spatially-coloured butterfly MNE draws for sensors (and plot_average reuses). That one is unavailable here because it interpolates onto a head surface, which parcel centroids do not lie on; this reproduces the part that carries the meaning -- where a trace comes from, readable off its colour -- without the topography. Colour encodes position directly (red = right, green = anterior, blue = left), and the panel on the right shows each region as a dot in a top-down head outline, so a colour in the butterfly can be traced back to a place.

    Needs region centroids: see core.TRFData.set_source_positions. For multi-column features the kernel is averaged over its sub-features, as in plot_average.

    plot_features ¶

    plot_features(
    specs: list | None = None,
    *,
    show_stats: bool = True,

    One column per feature: butterfly, masked image and peak topomap.

    The summary figure of a fitted model or cohort. Each feature gets a column of three stacked rows sharing a delay axis:

    1. the butterfly of the kernel (averaged over sub-features), with the significant delay intervals shaded green/red;
    2. for a scalar feature, the channels x time image with the non-significant region greyed out; for a multi-column one, a sub-features x time heatmap of the channel-collapsed coefficient (channel_reduce; see plot_average for what the two reducers mean and why they are drawn on different colour scales).     3. a topomap at the delay carrying the most significant channels (falling back to the GFP peak when nothing is significant), significant sensors marked, with its own colorbar.

    Needs sensor positions, for the topomap of row 3; without them, use plot_average. Significance comes from _plot_stats, so the figure renders unshaded -- and rows 2/3 unmasked -- for a lone TRFModel or a SubjectPlots, where a cohort cluster test does not exist.

    plot_bootstrap ¶

    plot_bootstrap(
    subject_ids: list | None = None,
    kind: str = "violin",
    channel_reduce: str | int = "mean",
    ci: float | None = 95,
    sort: bool = False,
    title: str | None = None,
    save_path: str | PathLike | None = None,
    show: bool = False,
) -> Figure

    Compare the per-subject bootstrap metric distributions side by side.

    Each subject fitted with bootstrap=True carries a (n_resamples, n_channels) distribution of the held-out metric, built by resampling contiguous blocks with replacement. This figure puts one violin (or box) per subject on a shared axis, so the cohort is read as a whole: who is reliable, who is noisy, and how far apart they really are relative to their own spread.

    Three things are drawn on top of the distributions, because a violin alone is easy to over-read:

    • the observed metric (the one the subject actually scored) as a marker. It is not the centre of its bootstrap distribution in general, and the gap is worth seeing;
    • the percentile interval at ci as a vertical line -- the number one would report, drawn where it can be compared across subjects;
    • the cohort mean of the observed metrics, as a horizontal reference.

    Parameters:

    Name Type Description Default
    subject_ids sequence

    Subjects to show, in this order. Default: every fitted subject, in fitting order.

    		 None
    kind (violin, box)

    "violin" shows the full shape (bootstrap distributions are often skewed); "box" is the compact option for many subjects.

    		 "violin"
    channel_reduce (mean, median, max)

    How the channel axis is collapsed to one value per resample. An int selects a single channel. The observed metric is collapsed the same way, so marker and distribution stay commensurate.

    evoked_to_stc¶

    evoked_to_stc ¶

    evoked_to_stc(
    evoked: Evoked, labels: list, src: SourceSpaces
) -> SourceEstimate

    Paint a region-wise Evoked onto the cortex as a SourceEstimate.

    Parcellated results have one value per region, but MNE's brain rendering wants one per vertex. Every vertex of a label therefore takes its region's value, giving the flat, uniformly-coloured parcels that make a parcellation figure readable as such.

    Rendering is deliberately left out: the returned stc takes the whole of mne.SourceEstimate.plot (hemispheres, views, colormaps, time viewer) without this package wrapping and re-exposing any of it, and no 3D backend is pulled in unless you call it.

    Parameters:

    Name Type Description Default
    evoked Evoked

    Channels named after the labels -- e.g. models.TorchTRF.to_evoked output for source-space targets. Names carrying MNE's -0/-1 uniqueness suffixes also match, the first such channel winning.

    		 required
    labels list of mne.Label

    The parcellation, e.g. from mne.read_labels_from_annot. Labels with no matching channel are left at zero.

    		 required
    src SourceSpaces

    The surface source space (two hemispheres) defining the vertices to paint. Its vertno sets the stc's vertices.

    		 required

    Returns:

    Type Description
    SourceEstimate

    Examples:

    >>> labels = mne.read_labels_from_annot(
...     "fsaverage", parc="aparc", subjects_dir=sd)
>>> stc = evoked_to_stc(
...     group.to_stc("envelope", labels, src), labels, src)
>>> brain = stc.plot(subject="fsaverage", subjects_dir=sd, hemi="split")
