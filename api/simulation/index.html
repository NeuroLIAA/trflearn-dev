    Simulation¶

    trflearn.simulation builds recordings whose answer is known: the only data on which recovering a kernel can be checked instead of argued. It is opt-in (import trflearn.simulation, never imported by the rest of the package) and its event tables need pandas, which comes with the simulation extra; see Installation. The tutorials use every part of it.

    Two ways to build a recording:

    • simulate, multichannel and for any features: a continuous stimulus from envelope / spectrogram, impulse trains from an event table, or both. It returns the TRFData a model is built from and the GroundTruth that model should recover.
    • EEGSimulator, one channel, event by event, where each event's covariates can modulate the response through a kernel's modifier.

    Simulating a recording¶

    simulate ¶

    simulate(
    features: dict[str, ndarray | list[ndarray]],
    kernels: dict[str, ndarray],
    sample_rate: int,
    *,
    info: Info | None = None,
    snr_db: float = 0.0,
    noise_colour: str = "white",
    rng: Generator | int | None = None,
    **data_kwargs: Any
) -> tuple[TRFData, GroundTruth]

    Simulate one recording with known kernels, ready to model.

    Each feature with a kernel is convolved with it, the responses add up, and noise is added at snr_db against that sum. Features without a kernel are kept: they reach the model and carry no response.

    Parameters:

    Name Type Description Default
    features dict of str to np.ndarray or list of np.ndarray

    The stimulus, as TRFData takes it: per feature an (n_samples, n_subfeatures) array, or a list of them, one per segment.

    		 required
    kernels dict of str to np.ndarray

    Per feature, (n_channels, n_subfeatures, n_delays) at lags 0, 1, ... samples: the layout of a fitted model's coef_. spatiotemporal_kernel builds one from waveforms and topographies.

    		 required
    sample_rate int

    Sampling rate in Hz.

    		 required
    info Info or None

    Channel info with the montage, one channel per kernel row. Passed to TRFData, so the montage-based figures work. None leaves the targets as plain arrays.

    		 None
    snr_db float

    Signal-to-noise ratio in dB, measured on the noise-free signal over every segment and channel. np.inf adds no noise.

    		 0.0
    noise_colour (white, pink, brown)

    Colour of the noise, independent across channels.

    		 "white"
    rng (Generator, int or None)

    Source of randomness for the noise, or a seed for one.

    		 None
    **data_kwargs Any

    Passed on to TRFData, e.g. precision or use_gpu.

    		 {}

    Returns:

    Name Type Description
    data TRFData

    The features and the simulated targets, in the layout of features.
    truth GroundTruth

    The injected kernels.

    Raises:

    Type Description
    ValueError

    If a kernel names a feature not in features, is not 3-D, does not match its feature's columns, or the kernels and info disagree on the number of channels.

    Examples:

    >>> info = make_info(["Fz", "Cz", "Pz", "Oz"], 128)
>>> p1n1 = (
...     CompoundKernel("envelope", 128)
...     .add(0.05, 1.0, 0.02)
...     .add(0.1, -1.5, 0.03)
... )
>>> kernel = spatiotemporal_kernel(
...     p1n1.waveform, gaussian_topography(info, [0, 0, 1])
... )
>>> data, truth = simulate(
...     {"envelope": envelope(128 * 60, 128, rng=0)},
...     {"envelope": kernel}, 128, info=info, snr_db=-5, rng=0,
... )

    The ground truth¶

    GroundTruth inherits the shared figures, so the injected kernels are drawn exactly as a fitted model's: truth.plot_average("envelope") beside model.plot_average("envelope").

    Continuous stimuli¶

    continuous_stimuli.py — Speech-like predictors: an envelope, a spectrogram.

    Both are band-limited noise, rectified: not speech, but with the property that matters for a TRF, energy confined to the syllabic modulation band, so the lagged design is as ill-conditioned as a real envelope's. envelope is one column. spectrogram is one envelope per acoustic band, and the bands share part of their modulation, as they do in speech: band_correlation sets how much, as the expected correlation between any two bands.

    Both return float arrays of shape (n_samples, n_columns), non-negative and of unit standard deviation per column, and the same rng seed gives the same stimulus.

    Discrete stimuli¶

    discrete_stimuli.py — Event tables: when events happen and what they carry.

    An experiment is a table with one row per event: its type, its onset latency in samples, and any covariates. TrialStructure draws the covariates from TrialVariable specifications, an ISI sampler spaces the onsets (assign_event_latencies), and ExperimentDesign does both in one call, then turns the table into one impulse train per event type: the features a TRFData takes. to_features does that conversion for any table, and adds each covariate as an amplitude at its event's onsets, the input spline_basis(scope="event") expects.

    The tables are pandas DataFrames. pandas is imported where it is used and ships with the simulation extra.

    to_features ¶

    to_features(
    events: DataFrame,
    n_samples: int,
    *,
    by: str = "type",
    values: dict[str, list[str]] | None = None
) -> dict[str, ndarray]

    Turn an events table into the features a TRFData takes.

    One impulse train per event type, and per requested covariate a train that holds the covariate's value at each onset of its type: an event's amplitude, a word's surprisal.

    Parameters:

    Name Type Description Default
    events DataFrame

    One row per event, with a latency column in samples.

    		 required
    n_samples int

    Length of the recording, in samples. Onsets outside it are dropped.

    		 required
    by str

    The column whose values name the event types.

    		 'type'
    values dict of str to list of str or None

    {event_type: [column, ...]}: for each, a feature named "{event_type}_{column}".

    		 None

    Returns:

    Type Description
    dict of str to np.ndarray

    (n_samples, 1) arrays, in order of first appearance: each type's impulse train, followed by its covariates. Events sharing a sample add up, as their responses do.

    Raises:

    Type Description

    Kernels¶

    kernels.py — The responses a simulation injects.

    An ERPKernel is one component, a Gaussian or Hann bump at a peak latency, whose amplitude can depend on the event through a modifier. A CompoundKernel sums several of them under one name, and is what recordings.EEGSimulator registers. Kernels are causal: their time axis starts at the event onset.

    Montage helpers¶

    recordings.py — Continuous recordings with known kernels buried in them.

    simulate builds a multichannel recording from any features: per feature a kernel of shape (n_channels, n_subfeatures, n_delays), the layout of a fitted model's coef_, convolved with the stimulus and summed, plus noise at a requested signal-to-noise ratio. It returns the TRFData a model is built from and the GroundTruth the model should recover. simulate_cohort repeats it for subjects who share the stimulus and the kernels, each with their own noise and gain.

    EEGSimulator builds one channel, event by event: per event and per kernel component, a stick whose height is 1 + modifier(**event_row), convolved with the component's waveform and summed, plus white, pink or brown noise.

    The montage helpers spread a time course or a kernel over a scalp layout: make_info builds an mne.Info with sensor positions, and gaussian_topography / project_to_channels give it a smooth spatial distribution, e.g. posterior for a visual response or fronto-central for a motor one. mne is imported where it is used.
