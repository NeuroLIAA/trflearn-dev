    Models¶

    TRFModel(...) is the factory; it returns a PooledTRF, AveragedTRF or TrainTestTRF, all of which inherit the estimator API below. See the concept page for the narrative.

    The factory¶

    TRFModel ¶

    TRFModel(
    TRFDataset: TRFData,
    features: list,
    *args: Any,
    cv: Literal["pooled"] = ...,
    **kwargs: Any
) -> PooledTRF

    TRFModel(
    TRFDataset: TRFData,
    features: list,
    *args: Any,
    cv: Literal["averaged"],
    **kwargs: Any
) -> AveragedTRF

    TRFModel(
    TRFDataset: TRFData,
    features: list,
    *args: Any,
    cv: Literal["train_test"],
    **kwargs: Any
) -> TrainTestTRF

    TRFModel(
    TRFDataset: TRFData,
    features: list,
    *args,
    cv: str = "pooled",
    **kwargs
) -> PooledTRF | AveragedTRF | TrainTestTRF

    Build a TRF model, choosing the cross-validation paradigm with cv.

    A single entry point that dispatches to the paradigm class and returns its instance:

    • cv="pooled" -> PooledTRF (standard k-fold): for each test fold, one model is fit on the pooled complement and predicts the held-out set. The default; recommended for everyday use.
    • cv="averaged" -> AveragedTRF (Crosse-Lalor): one model is fit per partition and each fold is predicted by the leave-one-out average of the other partitions' models. Mildly optimistic -- the held-out fold is standardized with its own statistics (see AveragedTRF).
    • cv="train_test" -> TrainTestTRF: a single contiguous train/test split; the λ that scores best on the test fold is kept, and train_size sets the split. The simplest option, but optimistic -- λ is selected on the reported set (see TrainTestTRF).

    Parameters:

    Name Type Description Default
    TRFDataset TRFData

    The data container, as in models.TorchTRF.

    		 required
    features list

    The selected features, as in models.TorchTRF.

    		 required
    cv (pooled, averaged, train_test)

    The cross-validation paradigm. Keyword-only.

    		 "pooled"
    *args

    Forwarded unchanged to the paradigm's constructor -- every argument of models.TorchTRF, plus train_size for cv="train_test".

    		 ()
    **kwargs

    Forwarded unchanged to the paradigm's constructor -- every argument of models.TorchTRF, plus train_size for cv="train_test".

    		 ()

    Returns:

    Type Description
    (PooledTRF, AveragedTRF or TrainTestTRF)

    A ready-to-fit model of the selected paradigm. The three overloads let a type checker resolve which one from a literal cv, so an editor can show the estimator's own methods on the result.

    Raises:

    Type Description
    ValueError

    If cv is not one of the three paradigms.

    The estimator API¶

    Every paradigm shares these methods, defined on the base estimator TorchTRF (fit, gridsearchCV, predict, to_evoked, …). The design report (diagnostics, information_criteria, vif_, aic_, …) is documented under Diagnostics, and the plotting methods under Plotting.

    TorchTRF ¶

    TorchTRF(
    TRFDataset: TRFData,
    features: list,
    default_window: tuple,
    feature_windows: dict | None = None,
    feature_bases: dict | None = None,
    feature_groups: dict | None = None,
    feature_preprocess: str | None = "Standardize",
    target_preprocess: str | None = "Standardize",
    solver: str = "ridge",
    delay_margin: float = 0.0,
    drop_zero_rows: bool = False,
    drop_warn_fraction: float = 0.25,
    verbose: int | str | bool | None = None,
)

    Base TRF estimator: delayed linear models with regularization.

    Fits at a fixed λ (fit), or selects one over a grid and refits (gridsearchCV); either can also return a block-bootstrap distribution of the channel-wise metric. predict and to_evoked read the result, and save writes it.

    The design report (diagnostics, information_criteria, vif_, aic_, …) comes from diagnostics.ModelDiagnosticsMixin and the figures from plots.ModelPlots.

    Initialize a delayed ridge-style TRF estimator over named features.

    The design is assembled block-by-block (feature-first): each selected feature (a base key or an interaction tuple) contributes its own lagged sub-design with its own delay window, concatenated horizontally. The penalty is block-diagonal (one penalty per feature over its own delays); for a single feature with the global window this is identical to the classic single-block design.

    Parameters:

    Name Type Description Default
    TRFDataset TRFData

    The (already partitioned) data container. Provides y, folds, relevant_indexes, the global delays window, device/precision, and lazy get_feature(name) access.

    		 required
    features list

    Selected features: each entry is a base key (str) or a tuple of keys (("k1","k2")) for an interaction (outer product of the raw features). An interaction expands to the product of its constituents' column counts.

    		 required
    default_window tuple of float

    (tmin, tmax) in seconds, the delay window every feature uses unless feature_windows overrides it.

    		 required
    feature_windows dict

    {spec: (tmin, tmax)} in seconds overriding the window of a feature/interaction. Defaults: a base feature without an entry uses the global window; an interaction without an entry uses the union of its constituents' specified windows (or the global window if none were specified). Windows are independent: a feature may extend beyond default_window. The container's crop window is the union of default_window and every entry here, so every resolved window is covered by construction. Keys must be among the selected features (a key that is not raises KeyError).

    		 None
    feature_bases dict

    {spec: transformer} attaching a basis expansion to a feature's amplitude, keyed like feature_windows. transformer is any scikit-learn-style object with fit/transform: the raw columns (n_samples, n_subfeatures) are mapped to (n_samples, n_subfeatures * k) before lagging, so a scalar feature becomes k smooth basis channels. Fitted once on the relevant stimulus (knots never see the target) and reused across folds and in predict.

    For splines, prefer trflearn.bases.spline_basis over a bare SplineTransformer: it drops one column per input feature, without which the block is exactly singular under feature_preprocess and regularization ends up holding it together rather than only regularizing it. Any other transformer is accepted, pipelines included. See Features, interactions & windows in the docs for the full argument and for composing a basis with an elementwise transform.

    An event feature -- zero wherever no event occurred, like a saccade's amplitude -- takes spline_basis(scope="event"), or trflearn.bases.event_scoped around any other transformer: the basis is fitted on the events and the empty rows stay zero. Expanded per sample instead, every empty row reads as an event of amplitude 0 and the quantile knots collapse onto those zeros.

    		 None
    feature_groups dict

    {band: [spec, ...]} grouping the selected features into bands, each of which gets its own regularization -- a banded ridge. The canonical use is two bands, an acoustic one and a linguistic one, so that a 16-column spectrogram and a 1-column surprisal are not forced to share a regularization strength their very different column counts and signal-to-noise ratios do not justify.

    One rule covers every case: a spec that is not listed in any band is its own band. So None (the default) makes every feature a band, and a partial mapping needs no filler entries for the features left out. Band order is the declaration order of feature_groups first, then the unlisted specs in features order -- deterministic, so it can be serialized and reported against.

    That the default is one band per feature rather than one band overall costs nothing: a scalar regularization broadcasts to every band, so a model built and fitted without ever mentioning bands is the same model, to the bit, that it was before bands existed. Bands are the resolution available, not a resolution imposed.

    Keys of the lists are specs, written exactly as in features (a string, or a tuple/list for an interaction). A spec listed twice, or a spec that is not among the selected features, is an error.

    See trflearn.search for how the per-band grid is then swept, and gridsearchCV for what regularization_grid accepts once bands exist.

    		 None
    feature_preprocess str or None

    'Standardize', 'Normalize', or None for no normalization. Applied per feature block and to the targets respectively. target_preprocess='Normalize' is deprecated and will be removed: with no intercept, a target that is not centred cannot be fitted.

    		 'Standardize'
    target_preprocess str or None

    'Standardize', 'Normalize', or None for no normalization. Applied per feature block and to the targets respectively. target_preprocess='Normalize' is deprecated and will be removed: with no intercept, a target that is not centred cannot be fitted.

    		 'Standardize'
    solver str

    'ridge', 'ridge-laplacian' or 'cross_corr' (see solvers). 'ridge-laplacian' smooths without shrinking: do not use it for a predictor that carries little signal.

    		 'ridge'
    delay_margin float

    Margin in seconds added on each side of every feature's window to absorb ridge edge-ringing (converted to lags via the sample rate). Trimmed off the kernel before predicting. Sizes the container's inter-segment buffer at materialization.

    		 0.0
    drop_zero_rows bool

    Exclude from the coefficient estimation the samples at which no feature block has any predictor -- the entirely-zero design rows that sparse features (word onsets, fixations, blinks) produce when no continuous feature accompanies them. Off by default, matching mTRF-Toolbox and Eelbrain, which fit on every sample. Prediction and scoring are unaffected either way; score_on in fit is what restricts the scored samples.

    It does not change the family of fitted models, only what regularization means: with k the surviving fraction, coef(λ, drop=True) == coef(k * λ, drop=False). A grid tuned with one setting does not carry over to the other. See Features, interactions & windows in the docs for why the mask is read before standardization and before any basis.

    		 False
    drop_warn_fraction float

    Fraction of dropped samples above which a UserWarning reports the loss (once per model). Only consulted when drop_zero_rows is on. Set to 1.0 to silence it.

    		 0.25
    verbose (int, str, bool or None)

    How much this model prints, overriding the process-wide setting: "silent", "warning", "info" or "debug". None (the default) follows the global one -- see trflearn.verbosity.

    		 None

    Raises:

    Type Description
    ValueError

    If delay_margin is negative, drop_warn_fraction is outside [0, 1], solver is unknown, a preprocess kind is unknown, the container has no folds, or a window has tmax < tmin.
    KeyError

    If feature_windows, feature_bases or feature_groups names a spec that is not among the selected features.
    TypeError

    If a feature_bases value is not a transformer.

    info property writable ¶

    info: Info | None

    Channel info (with montage), or None for array targets.

    Read live from the container while there is one, so a montage attached to the TRFData after the model was built is still picked up -- TRFData.set_montage is meant to work that way. A model loaded from disk has no container, and falls back to the identities its file carried.

    fit ¶

    fit(
    regularization: float | dict | ndarray,
    metric: str = "Pearson",
    per_fold_metric: bool = False,
    bootstrap: bool = False,
    as_evoked: bool = False,
    n_resamples: int = 10000,
    random_state: int | None = 42,
    score_on: ScoreOn = None,
) -> tuple[dict, Tensor] | tuple[dict, Tensor, dict]

    Fit one TRF per fold at a fixed λ, and score the held-out folds.

    Parameters:

    Name Type Description Default
    regularization (float, dict or ndarray)

    The regularization strength. A scalar applies to every band, a {band: value} mapping or a vector in band order sets them individually.

    		 required
    metric str

    Any name, label or alias in the metrics registry.

    		 'Pearson'
    per_fold_metric bool

    Score each fold separately instead of scoring the concatenated predictions once. Cannot be combined with bootstrap.

    		 False
    bootstrap bool

    Also return a block-bootstrap distribution of the metric.

    		 False
    as_evoked bool

    Also export the fitted kernels to MNE Evoked in coef_as_evoked_. The return value is unchanged.

    		 False
    n_resamples int

    Resamples to draw. Only consulted when bootstrap=True.

    		 10000
    random_state int or None

    Seed for the resampling, fixed by default so two runs of the same model report the same interval. Only consulted when bootstrap=True.

    		 42
    score_on (str, list, dict, ndarray, callable or None)

    Which held-out samples the metric is computed on. None (the default) scores every one: how much of the recording the model explains. The other forms keep the samples where a sparse feature can predict something, which is what an event-locked question asks:

    "informative" where any block has an event within its delay window. [spec, ...] where one of the named blocks has an event within its delay window. The form to use when a continuous feature beside them makes every sample informative. {spec: (tmin, tmax)} from tmin to tmax seconds after each event of spec, a window of its own inside the model's delay range. spec may be a container feature the model does not fit, so that two models can be scored on the same samples. boolean array one entry per real sample of the container, as for relevant_indexes. callable called with the held-out samples' real sample numbers, and returning one boolean per number.

    An event is a sample where the raw feature, before any basis, is non-zero. Only the scoring changes: the estimation and predict do not, and drop_zero_rows stays independent. The bootstrap and per_fold_metric see the same samples. scored_on_ records the selection and the fraction of held-out samples it kept, and metric_name_ is marked, e.g. "Pearson (onsets)": such a metric is not comparable to one over every sample.

    		 None

    Returns:

    Name Type Description
    trfs dict

    {spec: (n_folds, n_channels, n_subfeatures, n_delays)}, one kernel per selected feature.
    metric Tensor

    (n_folds, n_channels) with per_fold_metric=True, otherwise (n_channels,) over the concatenated predictions.
    distribution dict

    Only with bootstrap=True, and appended third: {"n_samples", "distribution", "random_state"}.

    Raises:

    Type Description
    ValueError

    If per_fold_metric and bootstrap are both set, or score_on is malformed or keeps fewer than two samples of a fold.
    KeyError

    If score_on names a feature the model does not fit (list) or the container does not hold (dict).
    TypeError

    If score_on is none of the forms above.
    RuntimeError

    If the model was loaded without its data.
    Notes

    coef_ (the fold-averaged kernels) is populated afterwards. The numerical diagnostics are not: they are computed on demand by diagnostics.

    gridsearchCV ¶

    gridsearchCV(
    regularization_grid: (
        list | ndarray | dict | None
    ) = None,
    inner_train_cutoff: float = 0.8,
    metric: str = "r2",
    metric_aggregation_function: str | int = "mean",
    metric_limit_percentage: float | None = None,
    validation_plot: bool = True,
    plot_path: str | PathLike = "validation_plot.png",
    run_fit: bool = True,
    run_fit_kwargs: dict | None = None,
    score_on: ScoreOn = None,
) -> tuple

    Select one λ by aggregating inner-validation metrics across folds.

    Parameters:

    Name Type Description Default
    regularization_grid (list, ndarray, dict, BandSearch or None)

    The λ values to try. search.as_search decides between:

    None (the default) search.DEFAULT_REGULARIZATION_GRID, np.logspace(-3, 3, 13). 1-D sequence the ordinary regularization grid. This is always its meaning, even for a model whose band count happens to equal the grid length; per-band values go one of the other two ways. {band: grid} a Cartesian product per band (search.band_grid). search.BandSearch a prepared space, e.g. from search.random_bands, which is what to reach for past two or three bands.

    		 None
    inner_train_cutoff float

    Fraction of each training partition that estimates; the rest scores the λ values.

    		 0.8
    metric str

    Any name, label or alias in the metrics registry. It chooses λ and, with run_fit=True, is the metric the refit reports. The default, 'r2', suits kernels that are interpreted: R² charges for shrinkage, which Pearson's correlation cannot see. Pass 'Pearson' when prediction accuracy is the result.

    		 'r2'
    metric_aggregation_function str or int

    How to collapse the per-fold metrics: 'mean', 'median', 'max' or a fold index. See _aggregate_folds for what each does and for the caveat on 'max'. 'mean' is the package-wide default, shared by every paradigm so that the λ each one selects -- and therefore the metric each one reports -- is arrived at the same way and stays comparable across them. It is less robust than 'median' to a single bad fold.

    		 'mean'
    metric_limit_percentage float or None

    Prefer the largest λ whose metric is within this fraction of the best. See _select_regularization. It shrinks the kernels without improving their shape: a Pearson curve is nearly flat over decades of λ, so even 0.01 can buy a much larger λ and 0.05 can shrink the kernels to almost nothing. Leave it None when the kernels themselves are the result.

    		 None
    validation_plot bool

    Save the validation figure. The figure's ingredients are recorded either way, so validation_plot() can render it on demand.

    		 True
    plot_path str or PathLike

    Where to save it; parent directories are created.

    		 'validation_plot.png'
    run_fit bool

    Refit at the selected λ, populating coef_.

    		 True
    run_fit_kwargs dict or None

    Forwarded to fit on that refit.

    		 None
    score_on (str, list, dict, ndarray, callable or None)

    Which held-out samples are scored, as in fit. It applies to the samples that select λ as well as to the refit, so λ is tuned for the same question the reported metric answers.

    		 None

    Returns:

    Name Type Description
    best_regularization float or dict

    A float for a plain grid, a {band: value} mapping once the bands were actually varied -- so a caller that never asked for bands never has to unpack one.
    result tuple or float

    fit's output with run_fit=True, otherwise the selected λ's aggregated metric.

    Raises:

    Type Description
    (ValueError, KeyError, TypeError)

    As in fit for a malformed score_on; a ValueError too if run_fit_kwargs also sets it.
    RuntimeError

    If the model was loaded without its data.

    predict ¶

    predict(X_new: dict | None = None) -> Tensor

    Predict the neural response from a stimulus using the fitted kernels.

    Sums each feature block's contribution: the (base or interaction) raw feature is standardized with the block's predict-time normalizer, lagged over its own delays, multiplied by coef_[spec], and accumulated; the total is mapped back to target units with the target normalizer.

    Parameters:

    Name Type Description Default
    X_new dict

    {name: (n_samples, n_subfeatures) array} of the base features the model uses (interactions are rebuilt from them). None (default) predicts on the model's own relevant stimulus.

    		 None

    Returns:

    Type Description
    Tensor

    Predicted response (n_samples, n_channels) in target units.

    to_evoked ¶

    to_evoked(info: Info | None = None) -> dict

    Return the fitted kernels as MNE Evoked objects.

    Parameters:

    Name Type Description Default
    info Info

    Channel info (with montage) to attach. Defaults to the info captured from the input Raw (TRFData.info). Pass one explicitly when the dataset was built from plain arrays, or to override the montage. Its channel count must match coef_ and its sfreq the model's sample_rate.

    		 None

    Returns:

    Type Description
    dict

    {spec: Evoked} for a single-column feature, and {spec: list of Evoked} for a wider one -- see below.

    Raises:

    Type Description
    RuntimeError

    If the model has not been fitted.
    ValueError

    If there is no channel info to attach.

    Warns:

    Type Description
    UserWarning

    When a feature has more than one sub-feature, since a list comes back where a single object might be expected.
    Notes

    Each kernel is (n_channels, n_subfeatures, n_delays) and an Evoked is strictly channels x time, so the response channels become the Evoked channels (inheriting the montage) and the feature's delays become the time axis (delays / sample_rate seconds, possibly negative). The sub-feature axis has nowhere to go in a single Evoked, so a feature with more than one column comes back as a list of them, one per column, tagged in comment.

    Crosse-Lalor TRF over TRFData (the cv="averaged" paradigm).

    One model is fit per partition; each fold is predicted by the leave-one-out average of the other partitions' models. Mildly optimistic: each partition is standardized with its own statistics and reused, so a held-out fold's features are z-scored with their own statistics (a small feature-scale leakage; see TorchAveragedTRF). Built via TRFModel(..., cv="averaged").

    Bases: TorchTrainTestTRF

    Simple single train/test split TRF (the cv="train_test" paradigm).

    One contiguous split: the model is fit on the train fold across the whole regularization grid and each λ is scored by its metric on the test fold; the λ that scores best there is kept. No inner validation, no fold aggregation -- the simplest possible workflow. Built via TRFModel(..., cv="train_test").

    Caveat. λ is selected on the same set whose metric is reported, so the reported metric is optimistic: the max over the grid, not an unbiased generalization estimate. Recommended only for a quick look; use cv="pooled" or cv="averaged" when the metric must be trustworthy.
