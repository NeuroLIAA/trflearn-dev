    Bases: GroupPlots

    Fit one model spec across a cohort and aggregate the results.

    Parameters:

    Name Type Description Default
    features list

    Feature specs (strings / interaction tuples), exactly as for TRFModel.

    		 required
    default_window tuple of float

    (tmin, tmax) in seconds — the fallback delay window, forwarded to each subject's TRFModel. Required.

    		 required
    cv str

    Cross-validation paradigm passed to TRFModel ("pooled", "averaged" or "train_test").

    		 "pooled"
    feature_windows dict or None

    Per-feature delay windows, forwarded to TRFModel.

    		 None
    feature_bases dict or None

    Per-feature basis expansions, already fitted, which every subject shares unchanged. That is what makes a spline column the same function of the stimulus in every subject, and so what lets the cohort average its kernels; refitted per subject, the knots would follow each subject's own stimulus. Fit each basis once on a stimulus that covers the whole cohort -- the subjects' feature arrays concatenated, say -- and pass it fitted. A subject whose bases differ from the ones the cohort was fitted with is refused.

    		 None
    feature_groups dict or None

    {band: [spec, ...]} grouping features into bands with their own regularization (a banded ridge), forwarded to TRFModel. Every subject of a cohort shares one band structure, so the per-band λ values each of them selects are comparable across the cohort; summary reports the scalar summary and each subject's record keeps the per-band detail.

    		 None
    feature_preprocess str

    Standardization choices, forwarded to TRFModel.

    		 'Standardize'
    target_preprocess str

    Standardization choices, forwarded to TRFModel.

    		 'Standardize'
    solver str

    Solver, forwarded to TRFModel.

    		 "ridge"
    delay_margin float

    Ridge edge margin (seconds), forwarded to TRFModel.

    		 0.0
    drop_zero_rows bool

    Estimate coefficients only where some feature block has a predictor, forwarded to TRFModel. Part of the cohort spec on purpose: it rescales what regularization means, so a cohort must not mix the two settings across subjects. See models.TorchTRF for the derivation.

    		 False
    drop_warn_fraction float

    Threshold above which the dropped-sample warning fires, forwarded to TRFModel. Warned once per subject model.

    		 0.25
    diagnostics bool

    Compute each subject's design diagnostics and record them. Off by default because they are not a product of fitting: each one costs a full extra pass over that subject's design (see models.TorchTRF.diagnostics), and a cohort pays it once per subject. With it off, condition_number, effective_rank, vif and n_aliased are None in every record. With it on, the collinearity report is included -- one more (n_columns, n_columns) decomposition on a pass that is already being paid for -- because a diagnostic that cannot be read across subjects does not say whose design is the odd one out. Overridable per subject via fit_subject(..., diagnostics=True).

    		 False
    criteria bool

    Record each subject's information criteria (AIC, BIC, the effective degrees of freedom, and the two quantities that identify the data they were computed on). Off by default for the same reason: it is a full extra pass over each subject's design. With diagnostics also on, both reports come out of one pass rather than two.

    This is what compare_to needs, and it has to be decided before fitting: the cohort discards each subject's model, so a comparison cannot be assembled after the fact without refitting. Overridable per subject via fit_subject(..., criteria=True).

    		 False
    regularization_grid array - like or None

    Regularization grid searched per subject when fit_method="gridsearch". None searches search.DEFAULT_REGULARIZATION_GRID, np.logspace(-3, 3, 13).

    		 None
    metric str

    Chooses each subject's λ and scores each subject. R² suits the kernels a cohort is fitted for; pass "Pearson" when prediction accuracy is the result.

    		 "r2"
    score_on (str, list, dict or None)

    Which held-out samples every subject's metric is computed on, as in models.TorchTRF.fit: "informative", a list of features or a {feature: (tmin, tmax)} window. None (the default) scores every sample. Only these declarative forms are shared by a cohort; a boolean array or a callable describes one recording, so it goes to that subject's fit_subject. The figures' metric label is marked with it, and each record keeps scored_on.

    		 None
    bootstrap bool

    If True, store each subject's bootstrap metric distribution.

    		 False
    n_resamples optional

    Forwarded to the backend's bootstrap when bootstrap=True. None (the default) leaves the backend's own values in place -- 10,000 resamples and a fixed seed, so every subject's interval is reproducible and, since the seed does not vary with the subject, comparable across the cohort. Overridable per subject in fit_subject.

    		 None
    random_state optional

    Forwarded to the backend's bootstrap when bootstrap=True. None (the default) leaves the backend's own values in place -- 10,000 resamples and a fixed seed, so every subject's interval is reproducible and, since the seed does not vary with the subject, comparable across the cohort. Overridable per subject in fit_subject.

    		 None
    fit_method (gridsearch, fit)

    How each subject is fitted. "gridsearch" sweeps regularization_grid with the paradigm's gridsearchCV and refits at the selected λ; "fit" skips the search and fits directly at regularization.

    		 "gridsearch"
    regularization float or None

    Fixed regularization used when fit_method="fit". Required in that mode (here or per subject).

    		 None
    regularization_strategy str or None

    How the subjects' λ values relate when fit_method="gridsearch". A noisier subject selects a larger λ and is shrunk more, so with a λ per subject a difference between subjects partly reflects their noise (see One λ for a whole group in docs/recommendations.md).

    "mean-curve", "median" One λ for the whole cohort, in two passes: search_subject on every subject, share_regularization, then fit_subject on every subject at that λ. "mean-curve" selects on the subjects' mean validation curve; "median" takes the geometric median of the λ values they chose on their own. fit_subject raises if it is called before share_regularization. "leave-one-out" One λ for the whole cohort, the one at which the other subjects' average kernel best predicts each subject, scored with metric. It needs every subject's kernels at every λ, so it keeps them whatever keep_kernels_by_regularization says, together with the sums of each subject's design. "subject" Each subject is searched and fitted at its own λ, in one loop of fit_subject. None (the default) As "subject", but the cohort warns once when its subjects end up at different λ values. Following the two-pass pattern shares one λ instead, by "mean-curve".

    		 None
    keep_kernels_by_regularization bool

    Have search_subject also fit each subject at every λ searched and keep those kernels in memory, so that share_regularization fills every subject's record at the shared λ and the second loop of fit_subject is not needed. Same compute as the two passes; what it saves is loading every subject twice, and what it costs is memory -- logged at INFO for the first subject, and refused before any fit past half of the memory available. The kernels are read with kernels_by_regularization and are not written by save. With bootstrap, diagnostics or criteria, which need the data, the second loop stays.

    		 False
    n_subjects int or None

    How many subjects the cohort will search, so that the memory the kept kernels take is checked for all of them before the first one is fitted. None checks the subjects searched so far, one at a time.

    		 None
    kernel_units (original, standardized)

    Units of every kernel the cohort hands out: results, subjects, grand_average, the cluster tests, the contrasts and the figures. "original" undoes the standardization, coef_ · σ_y / σ_x, giving the recording's unit per unit of each feature. "standardized" keeps the coefficients as fitted, in target standard deviations per feature standard deviation; since each subject is divided by their own σ_y, which contains their noise, a noisier subject's kernel comes out smaller. It can be changed after fitting: the grand average follows, and cluster tests run in the other units are cleared.

    		 "original"
    train_size float or None

    Train proportion of the single split, forwarded to the backend constructor. Only valid with cv="train_test".

    		 None
    inner_train_cutoff float or None

    Inner train/validation cutoff of the regularization search. Only valid with cv="pooled"; None keeps the backend default (0.8).

    		 None
    metric_aggregation_function (str, int or None)

    How per-fold validation metrics are aggregated for λ selection ("median"/"mean"/"max"/fold index). Not available with cv="train_test"; None keeps the backend default, which is "mean" in every paradigm.

    		 None
    metric_limit_percentage float or None

    If set, select the largest λ within this fraction of the best metric. It shrinks the kernels without improving their shape; leave it None when the kernels are the result.

    		 None
    per_fold_metric bool

    Report the metric per fold instead of over the concatenated folds. The cohort still stores the channel-wise metric, so aggregation is unaffected.

    		 False
    validation_plot bool or None

    Whether each subject's regularization search plot is saved. Defaults to False (the cohort loop is not interactive).

    		 None
    plot_dir (str, Path or None)

    Directory those plots go in, one validation_plot_<subject>.png per subject, created if it does not exist. A directory rather than a path because a cohort writes one figure per subject -- the single-figure TRFModel.gridsearchCV is the one that takes a plot_path. None writes them into the working directory.

    		 None
    verbose (int, str, bool or None)

    How much every subject's model prints, overriding the process-wide setting: "silent", "warning", "info" or "debug". None (the default) follows the global one. "warning" is the usual choice for a cohort -- numeric problems still surface, the per-subject status chatter does not. See trflearn.verbosity.

    		 None
    Notes

    Every parameter above is a default: fit_subject accepts the same names as per-subject overrides, plus any other keyword the selected paradigm's fit/gridsearchCV accepts (e.g. as_evoked). Parameters that the chosen cv does not support raise a TypeError naming what is available. A subject fitted with fit_method="fit" ignores the defaults that only configure the regularization search (inner_train_cutoff, metric_aggregation_function, metric_limit_percentage), so a group set up for the search can still fit a subject at a known λ; passed to that call explicitly, they raise.

    Subjects need not share a montage. Each one records its channel names, and every aggregate is computed over common_channels -- the intersection, in the first subject's order -- matching channels by name rather than by position. A cohort whose subjects all share the same montage is unaffected; one that does not warns once, naming the channels it drops.

    See Also

    call : the per-subject plotting view, group("s01").plot_*(...). plots.GroupPlots : the cohort's own figures, and the table of which figure works on which owner.

    Attributes:

    Name Type Description
    shared_regularization_ (float, dict or None)

    The cohort's λ after share_regularization: a float, or {band: value} for a banded search. None before, and in a cohort that does not share one. What it was chosen from is in regularization_search_.
    grand_average_ dict or None

    {spec: {"mean","std","sem","n"}} after grand_average, over common_channels.
    stats_ dict

    {spec: (t_obs, pvals)} after permutation_test / tfce.
    contrast_stats_ dict

    {spec: (t_obs, pvals)} after permutation_test_contrast, and {(spec_a, spec_b): ...} after permutation_test_contrast_features.
    info Info or None

    Channel info inherited from the first subject's TRFData (montage/types for adjacency and Evoked export). Restricted to common_channels wherever it labels an aggregate.
    common_channels list or None

    The channels every subject contributes; None for unnamed (array) targets, which are aligned by position instead.

    kernel_units property writable ¶

    kernel_units: str

    Units of every kernel the cohort hands out; see the class Parameters.

    Setting it recomputes the grand average on its next use and clears the cluster tests, which were run in the other units.

    subject_ids property ¶

    subject_ids: list

    Subject identifiers, in the order they were added.

    subjects property ¶

    subjects: MappingProxyType

    Read-only view of every fitted subject's stored result.

    {subject_id: {"coef_", "metric", "scored_on", "regularization", "bootstrap", "delays", "scales", "condition_number", "effective_rank", "vif", "n_aliased", "aic", "bic", "edf", "n", "target_ss", "ch_names"}} -- see results for what each entry holds. The mapping (and each record) rejects assignment, so the cohort cannot be mutated by accident; the arrays inside are the stored ones, not copies, so .copy() them before modifying in place. The kernels are the exception when kernel_units is "original": they are computed on each call.

    regularization_search_ property ¶

    regularization_search_: MappingProxyType | None

    What the cohort's λ was chosen from; None before any search.

    Returns:

    Type Description
    MappingProxyType or None

    regularization (n_values,), each λ searched: the value itself, or the global scale of a banded one -- the axis the curves are drawn over. metric The metric the curves are in, marked by score_on. curves {subject: (n_values,)}, each subject's validation curve. chosen {subject: λ}, what each subject's own search chose: a float, or {band: value} for a banded search. strategy The strategy share_regularization used, None before. cohort_curve (n_values,), the curve the shared λ was selected on: the mean curve or the leave-one-out one. None for "median", which selects on the choices, and before sharing.

    common_channels property ¶

    common_channels: list | None

    Channels in every fitted subject, in the first subject's order.

    The cohort does not require its subjects to share a montage: each one contributes the channels it has, and every aggregate (grand_average, summary, permutation_test, the group plots) is computed over this intersection. Channels missing from even one subject are dropped from all of them -- the same convention as picking a common set before a permutation test.

    Returns None when at least one subject was fitted from plain arrays with no channel names: nothing can be matched by identity there, so aggregation falls back to positional alignment and simply requires every subject to have the same number of channels.

    Raises:

    Type Description
    RuntimeError

    If no subject has been fitted yet.
    ValueError

    If the intersection is empty -- the cohort has no shared channel and there is nothing to average.

    results ¶

    results(subject_id: str | tuple) -> MappingProxyType

    Read-only access to one subject's stored result.

    Parameters:

    Name Type Description Default
    subject_id str or tuple

    An id passed to fit_subject. Unknown ids raise KeyError listing the cohort.

    		 required

    Returns:

    Type Description
    MappingProxyType

    Everything below is the subject's own, in the subject's own channel order -- not picked to common_channels.

    coef_ {spec: (n_channels, n_subfeatures, n_delays)}, the fold-averaged kernels, in the cohort's kernel_units. metric (n_channels,), the channel-wise held-out metric. scored_on {"score_on", "fraction"}: what the metric was restricted to and the fraction of held-out samples kept, or None when it covers every sample (see models.TorchTRF.fit). regularization, regularization_bands The regularization actually fitted, as a scalar summary and, for a banded ridge, the {band: value} detail. regularization_bands is None when the bands never varied. bootstrap {"n_samples", "distribution", "random_state"}, or None. delays {spec: lags} in samples. scales {"target": (n_channels,), "features": {spec: (n_subfeatures,)}}, what the subject's standardization divided by (None where nothing was divided). They take the fitted coefficients to original units. condition_number, effective_rank The design diagnostics, None unless the cohort was built with diagnostics=True. vif, n_aliased {spec: float}, each block's generalized VIF (Fox & Monette, 1992, as GVIF^(1/2d)), and how many design columns are exact linear combinations of the rest. Read them together: the GVIF is computed on a full-rank subset of the columns, so an exact dependency shows up in n_aliased rather than as a large GVIF -- two duplicated blocks read 1.0 each once the duplicate columns are set aside. 1.0 means nothing shared, nan the degenerate single-block case, 0 a healthy design. Both follow diagnostics=True. The per-column arrays behind them stay on the model and are not recorded; refit the odd subject to inspect them. aic, bic, edf (n_channels,) information criteria and the effective degrees of freedom, None unless the cohort was built with criteria=True. Lower is better, and a criterion means something only as a difference against another model of the same response -- which is what compare_to is for. n, target_ss How many rows entered this subject's fit and the raw y'y over them. They identify the data those criteria describe, and compare_to refuses a comparison when they disagree. ch_names This subject's channel labels, None for unnamed array targets. The axis order of coef_ and metric.
    See Also

    subjects : the same view for the whole cohort. call : the plotting view (group(subject_id).plot_*()).

    save ¶

    save(
    path: str | PathLike, *, with_bases: bool = False
) -> None

    Write the cohort to path (see trflearn.io).

    Nothing is lost: the cohort already keeps only compact arrays per subject, so one read back with trflearn.load(path) aggregates, tests, plots and keeps fitting subjects exactly like this one. The per-subject bootstrap distributions and the cluster-test results travel with it -- expensive to recompute, and the second is what shades the figures.

    Parameters:

    Name Type Description Default
    path str or PathLike

    Destination file; parent directories are created. .pkl is the convention, but the path is used verbatim.

    		 required
    with_bases bool

    Embed the feature_bases transformers, the only thing that ties a file to a library version. Without them a cohort that used bases still reads back whole; only fitting further subjects needs them set again, and trflearn.load says so.

    		 False
    See Also

    trflearn.io.save : the format, and what a version bump costs.

    search_subject ¶

    search_subject(
    TRFDataset: TRFData,
    subject_id: str | tuple,
    **overrides: Any
) -> TRFGroup

    Run one subject's regularization search and keep only its curve.

    The first of the two passes that fit a cohort at one λ::

    for subject_id in subject_ids:
    group.search_subject(load(subject_id), subject_id)
group.share_regularization()
for subject_id in subject_ids:
    group.fit_subject(load(subject_id), subject_id)

    The search is the one fit_subject would run, without the final fit. The model is discarded and the cohort keeps n_values floats per subject, from which share_regularization picks the λ.

    When the cohort keeps its kernels (keep_kernels_by_regularization or regularization_strategy="leave-one-out"), the subject is also fitted at every λ, as fit_subject would at each one, and the kernels and the metric are kept for share_regularization to fill the record with; leave-one-out keeps the sums of the subject's design too. The memory this takes is known before the fit: it is logged at INFO for the first subject and refused past the budget.

    Parameters:

    Name Type Description Default
    TRFDataset TRFData

    The subject's container, already partitioned.

    		 required
    subject_id str or tuple

    The key the curve is kept under, the same fit_subject takes.

    		 required
    **overrides Any

    Any keyword of fit_subject that configures the search (inner_train_cutoff, score_on, validation_plot, ...). Not regularization_grid or metric: the curves are averaged, so they must share one grid and one metric.

    		 {}

    Returns:

    Type Description
    TRFGroup

    self, so calls chain over a cohort.

    Raises:

    Type Description
    ValueError

    If the cohort fits each subject at its own λ (regularization_strategy="subject") or at a fixed one (fit_method="fit"), if the subject has already been searched, or if its search space differs from the other subjects'.
    TypeError

    If regularization_grid, metric, diagnostics, criteria or a keyword of the final fit is passed.
    RuntimeError

    If share_regularization has already run.
    MemoryError

    If the kernels the cohort keeps would pass the budget: half of the memory available, over n_subjects or the subjects so far.

    share_regularization ¶

    share_regularization(
    strategy: str | None = None,
) -> float | dict

    Choose the cohort's λ from every searched subject.

    The second of the two passes (see search_subject); fit_subject then fits every subject at the result. A cohort that kept its kernels is filled here instead, every searched subject's record at the shared λ, unless it asks for bootstrap, diagnostics or criteria, which need the data and leave the fit_subject loop in place.

    Parameters:

    Name Type Description Default
    strategy (mean - curve, median, leave - one - out)

    "mean-curve" selects on the subjects' mean validation curve, the way one subject's search selects on its own curve, so metric_limit_percentage applies. "median" takes the geometric median of the λ values the subjects chose on their own, snapped to the nearest λ searched. "leave-one-out" selects on how well the other subjects' average kernel predicts each subject, in the cohort's kernel_units, over common_channels, and also takes metric_limit_percentage; it needs the kernels and sums a cohort built with that strategy keeps. None uses the cohort's regularization_strategy, or "mean-curve" when that is unset. See group_regularization for the arithmetic.

    		 "mean-curve"

    Returns:

    Type Description
    float or dict

    The λ, also kept as shared_regularization_: a float for a plain grid, {band: value} for a banded search, which shares the whole vector. The curve it was selected on is in regularization_search_.

    Raises:

    Type Description
    ValueError

    If the strategy is not one of the three, the cohort fits each subject at its own λ (regularization_strategy="subject"), or "median" meets a λ that is not positive.
    RuntimeError

    If no subject has been searched, some were already fitted at their own λ, or "leave-one-out" lacks a subject's kernels.

    kernels_by_regularization ¶

    kernels_by_regularization(
    subject_id: str | tuple,
) -> MappingProxyType

    One subject's kernels at every λ searched, not only the shared one.

    Kept by search_subject when the cohort is built with keep_kernels_by_regularization=True or regularization_strategy="leave-one-out". They show how a subject's kernel changes with the regularization, and are what the leave-one-out and the one-pass fill read.

    Parameters:

    Name Type Description Default
    subject_id str or tuple

    An id passed to search_subject.

    		 required

    Returns:

    Type Description
    MappingProxyType

    regularization (n_values,), each λ searched: the value itself, or the global scale of a banded one, as in regularization_search_. coef_ {spec: (n_values, n_channels, n_subfeatures, n_delays)}; entry i is the kernel fit_subject would store at the i-th λ, in the cohort's kernel_units. metric (n_values, n_channels), the cross-validated metric at each λ.

    Raises:

    Type Description
    KeyError

    If the subject was not searched.
    RuntimeError

    If the cohort did not keep the subject's kernels.

    fit_subject ¶

    fit_subject(
    TRFDataset: TRFData,
    subject_id: str | tuple,
    **overrides: Any
) -> TRFGroup

    Fit the group's spec on one subject and store the minimal result.

    Builds a TRFModel with the group's spec, fits it the way the group was configured -- fit_method="gridsearch" (the paradigm's gridsearchCV, refitting at the selected λ) or fit_method="fit" (a direct fit at regularization) -- then extracts the fold-averaged kernels, the channel-wise metric, the fitted regularization and, if requested, the bootstrap distribution, and discards the model.

group.fit_subject(data, "s3", per_fold_metric=True, as_evoked=True)

    Keywords belonging to fit are routed through run_fit_kwargs when the regularization search runs, so both stages are reachable from one call and run_fit_kwargs itself is not accepted. A direct fit ignores the group's search-only defaults (see the class Notes).

    permutation_test ¶

    permutation_test(
    spec: str | tuple,
    threshold: float | dict | None = None,
    test_window: tuple[float, float] | None = None,
    **kwargs: Any
) -> tuple[ndarray, ndarray]

    Cluster permutation test that a feature's kernel differs from zero.

    Assembles the per-subject kernel maps for spec -- (n_subjects, n_delays, n_channels) for a scalar feature, or (n_subjects, n_delays, n_subfeatures, n_channels) for a multi-column one (no averaging: the sub-features enter the clustering as their own lattice dimension) -- builds the full adjacency (delay/sub-feature lattices x channel adjacency), and calls statistics.cluster_1samp. Stores and returns (t_obs, pvals) in stats_, each shaped like the map's non-subject dimensions.

    Subjects are aligned over common_channels, so a cohort recorded with different montages is tested on the electrodes it shares.

    See permutation_test_contrast for the paired version, which asks whether two cohorts' kernels differ from each other rather than from zero.

    Parameters:

    Name Type Description Default
    spec str or tuple

    The feature whose kernel is tested.

    		 required
    threshold (float, dict or None)

    A float runs the cluster-mass flavour with that cluster-forming t; a dict or None runs TFCE. See statistics.t_threshold for picking the float -- the degrees of freedom are len(group) - 1 -- and statistics.cluster_1samp for what each flavour's p-values mean.

    		 None
    test_window tuple of float or None

    (tmin, tmax) in seconds restricting the test to part of the kernel's delay axis, both ends inclusive. Narrowing an a-priori window shrinks the multiple-comparison space and buys power, at the cost of saying nothing about the delays left out. The result keeps the full delay length either way: untested delays come back with pvals = 1.0 and t_obs = NaN, so the figures shade a windowed result without knowing one was run.

    compare_to ¶

    compare_to(other: TRFGroup) -> CohortComparison

    Rank two cohorts by AIC and BIC, subject by subject.

    The group-level version of selection.compare: both cohorts hold the same subjects fitted under two different model specs -- envelope alone against envelope + onsets, say -- and the question is which spec describes this group of people better. A held-out metric cannot answer it, since adding a feature block almost never makes the fit worse; the criteria price the complexity, so they can.

    Parameters:

    Name Type Description Default
    other TRFGroup

    The cohort to compare against. Must hold exactly the same subject ids as self; subjects are paired by id, never by position.

    		 required

    Returns:

    Type Description
    CohortComparison

    The per-subject deltas and both aggregations of them, which documents every field. The sign is self - other and lower is better, so a positive delta favours other.

    Raises:

    Type Description
    RuntimeError

    If either cohort has no fitted subject.
    ValueError

    If the cohorts do not hold the same subjects, if either was fitted without criteria=True, or if any subject's two fits do not describe the same response -- different n, channel count or target_ss. A criterion difference across different data is not interpretable, and nothing in the arithmetic would notice.
    Notes

    Both cohorts must have been fitted with criteria=True, and that is a decision made before the loop: the cohort discards each subject's model after fitting, so the criteria cannot be assembled afterwards without refitting.

    The Wilcoxon is the honest test here, and for a reason worth stating: the per-subject criteria are overconfident, because both assume independent samples and EEG residuals are autocorrelated. That inflation is within a subject. Asking whether N independent subjects fell on the same side does not inherit it -- each subject contributes one observation, however overconfident their own number was.

    See docs/group-analysis.md for how to read the two aggregations against each other.

    Examples:

    >>> lean = TRFGroup(["envelope"], (-0.1, 0.4), criteria=True)
>>> rich = TRFGroup(["envelope", "onsets"], (-0.1, 0.4), criteria=True)
>>> ...  # fit the same subjects into both
>>> table = lean.compare_to(rich)
>>> table.best["bic"], table.n_favouring_self["bic"]
('self', 12)
>>> print(table.summary())

    Paired cluster permutation test of two features of the same model.

    The within-model counterpart of permutation_test_contrast. Where that one compares the same feature across two cohorts, this compares two features that were fitted jointly, in one design and one solve, for every subject.

    That joint fit is what makes the comparison clean, and it is the reason to prefer this over two separate models when the question allows it:

    • the two kernels are estimated controlling for each other, so shared variance between correlated regressors is split rather than handed whole to whichever regressor happens to be in the model;
    • they come from the same regularization, the same normalization, the same folds and the same sample count, so their difference carries no trace of a difference in regularization.

    The canonical use is a pair of condition-coded versions of one regressor -- attended vs unattended stream, left vs right, target vs distractor -- entered as two features of a single model.

    How a cohort chooses one λ¶

    The arithmetic behind share_regularization, on plain arrays.

    group_regularization ¶

    group_regularization.py -- how a cohort chooses one λ.

    Kernels compared across subjects need one λ for all of them: a noisier subject selects a larger λ and is shrunk more, so a λ per subject turns data quality into amplitude (One λ for a whole group in docs/recommendations.md). group.TRFGroup runs the loops over subjects and keeps their records; this module holds the arithmetic of the choice, on plain arrays -- no data, no model, no cohort -- so it can be read and tested on its own.

    Three strategies

    "mean-curve" (mean_curve, then select_index) Each subject's validation curve -- the metric of their own search at every λ, averaged over channels and aggregated over folds -- is averaged across subjects, each with the same weight, and the best point of that mean is chosen the way one subject's search chooses on its own curve. A noisy subject has a flat curve, so it moves the peak little although it weighs the same. "median" (median_index) The geometric median of the λ values the subjects chose on their own, snapped to the nearest λ searched. "leave-one-out" (leave_one_out_curve, then select_index) At every λ, the average kernel of the other subjects predicts each subject's recording, and the curve is that score averaged over channels and subjects. It asks the question the group-average kernel is for: how well a kernel estimated without a subject describes them. The inner benchmark found it closest to the best λ in hindsight for a strong predictor in heavy noise, where the mean curve over-regularizes.

    The leave-one-out needs every subject's kernel at every λ and the sums of every subject's design, which a cohort keeps in memory while it searches. kept_nbytes says exactly how much that takes per subject, and check_budget refuses before any fit when the cohort would not fit.

    Kernel layout

    A cohort records kernels as {spec: (n_channels, n_subfeatures, n_delays)}. The arithmetic here wants one coefficient matrix (n_columns, n_channels) in the column order of the design -- block after block, delay-first within a block. stack_kernels and column_scales translate.
