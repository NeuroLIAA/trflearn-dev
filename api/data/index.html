    TRFData¶

    The lazy, window-agnostic data container. See the concept page for the narrative.

    TRFData ¶

    TRFData(
    features: dict[str, ndarray | list[ndarray]],
    y: ndarray | list[ndarray] | BaseRaw | list,
    sample_rate: int,
    precision: str = "float32",
    relevant_indexes: ndarray | list | None = None,
    target_names: list[str] | None = None,
    use_gpu: bool = False,
    info: Info | None = None,
    verbose: int | str | bool | None = None,
)

    Bases: Dataset

    Reusable, lazy container of named stimulus features, targets and folds.

    Holds all candidate features by name, plus the targets and the cross-validation config, so a single instance can feed several models -- different feature subsets, different windows -- over the same recording.

    It does not take tmin/tmax: the delay window lives on the model (default_window / feature_windows). Construction computes only the cheap, values-free segment layout; the NaN buffer between segments, the buffer-safe sample set and the folds all wait for materialize, which a model triggers once it knows its crop window. Re-materializing for a different window recomputes them and invalidates the feature cache.

    Build a reusable, fully lazy TRF data container from named streams.

    Parameters:

    Name Type Description Default
    features dict[str, ndarray | list[ndarray]]

    Mapping name -> feature. Each feature is either a 2D array (n_samples, n_subfeatures) (single continuous recording) or a list of per-segment 2D arrays (samples_s, n_subfeatures) (segmented recording). All features must share the same layout as y (all 2D, or all lists with the same number of segments).

    		 required
    y np.ndarray, list of np.ndarray, mne.io.Raw, or list of mne.io.Raw

    Targets, in the same layout as the features: 2D (n_samples, n_channels) or a list of per-segment 2D arrays, or an MNE Raw / a list of Raw, one per segment. Raw input must match the features in length exactly, where plain arrays are trimmed to the per-segment minimum.

    		 required
    sample_rate int

    Sampling rate in Hz.

    		 required
    precision str

    "float32" or "float64".

    		 "float32"
    relevant_indexes ndarray or list

    Subset of samples used for folds and design. None = all buffer-free samples. Four forms are accepted:

    • an integer index array, already in concatenated coordinates;
    • a boolean mask with one entry per real sample, so its length is the sum of the segment lengths -- the inter-segment buffer is not part of it, since its width comes from the model's delay window and does not exist yet at construction time. A mask of any other length is an error;
    • in the segmented layout, a list of per-segment local index arrays, remapped to concatenated coordinates;
    • in the segmented layout, a list of per-segment boolean masks, each as long as its own segment. Entries are resolved one by one, so the list may mix both forms.

    Whatever the form, the result is intersected with the buffer-free set at materialization.

    These select rows of the design matrix and of the target, not samples of the raw feature: every feature is lagged over its whole series, in original time coordinates, and only then are these rows kept -- the same rows on both sides, so X and y stay aligned. A subset may therefore be arbitrarily gappy without its delays ever jumping across the gaps. Features and y must share the same original length for the indices to mean the same thing on both (see models.TorchTRF._make_gram_and_y for the full invariant).

    		 None
    target_names list of str

    Names for the targets (e.g. EEG channel labels). Ignored when info is given (or later attached): the channel names then come from it.

    		 None
    use_gpu bool

    If True, materialized features and targets live on CUDA.

    		 False
    info Info

    Channel info with a montage, for array-based targets. Equivalent to calling set_info afterwards, which documents what it unlocks and what degrades quietly without it.

    		 None
    verbose (int, str, bool or None)

    How much this container prints, overriding the process-wide setting: "silent", "warning", "info" or "debug". None (the default) follows the global one -- see trflearn.verbosity.

    		 None

    Raises:

    Type Description
    ValueError

    If precision is not one of the two supported values, if use_gpu is set without CUDA available, if features is empty or not a dict of string keys, if the feature and target layouts disagree, or if target_names does not match the channel count.

    raw_features property ¶

    raw_features: dict[str, ndarray | list[ndarray]]

    The features as passed, before any windowing or preprocessing.

    Per feature, an (n_samples, n_subfeatures) array or a list of them, one per segment: the layout they came in. They are read-only views, because the container keeps reading the same arrays; copy one to modify it.

    raw_targets property ¶

    raw_targets: ndarray | list[ndarray]

    The targets as arrays, before any windowing or preprocessing.

    An (n_samples, n_channels) array or a list of them, one per segment: the layout they came in. Targets passed as mne.Raw come back as the values read from them, in the Raw's units and with nothing rejected, since bad annotations only remove samples from relevant_indexes. Read-only views, as in raw_features.

    channel_identities ¶

    channel_identities() -> list[str] | None

    The channels' names, when the container knows them.

    Returns:

    Type Description
    list of str or None

    The info's channel names when there is an info; failing that, the target_names the user set; None otherwise. The generated "Target i" placeholders are never returned: they name a position, not a sensor, so matching recordings by them would be positional matching in disguise.

    set_info ¶

    set_info(info: Info) -> TRFData

    Attach MNE channel info (montage, channel types) to this container.

    The Raw ingestion path fills info on its own; this is the way in for array-based targets, whose montage would otherwise be missing for good. It unlocks models.TorchTRF.to_evoked, every montage-based figure, and -- the one that fails quietly rather than loudly -- the spatial adjacency of TRFGroup.tfce, which without a montage treats the channels as independent.

    The info's channel names become target_names, mirroring what the Raw path already does. Nothing else is affected: info is pure metadata and takes no part in materialization, so it may be attached before or after materialize / create_partitions without recomputing anything.

    Parameters:

    Name Type Description Default
    info Info

    Must describe exactly n_channels channels at sample_rate Hz. Both are checked here so a mismatch surfaces now rather than several steps later inside a plotting call.

    		 required

    Returns:

    Type Description
    TRFData

    self, for chaining.
    See Also

    set_montage : build the info from a montage plus channel names.

    Notes

    TRFGroup copies the info from the first subject it fits, so attach it before fit_subject (or assign group.info yourself afterwards).

    set_montage ¶

    set_montage(
    montage: str | DigMontage,
    ch_names: list[str] | None = None,
    ch_types: str | list[str] = "eeg",
) -> TRFData

    Build the channel info from a montage and attach it (see set_info).

    The shortcut for the common case: no Raw at hand, but the electrode layout is known. Creates an mne.Info for ch_names at the container's sample_rate, applies montage to it and stores it.

    Parameters:

    Name Type Description Default
    montage str or DigMontage

    A standard montage name (e.g. "standard_1020", "biosemi64") or a montage object.

    		 required
    ch_names list of str

    Channel names, in the order of the target columns. Defaults to the container's target_names — which only works if they are real electrode labels; the generated "Target i" placeholders are rejected with a message asking for explicit names.

    		 None
    ch_types str or list of str

    Channel types, forwarded to mne.create_info.

    		 "eeg"

    Returns:

    Type Description
    TRFData

    self, for chaining.

    Examples:

    >>> data = TRFData(features=feats, y=eeg_array, sample_rate=128)
>>> data.set_montage("standard_1020",
...                  ch_names=["Fz", "Cz", "Pz", "Oz"])

    set_source_positions ¶

    set_source_positions(
    positions: (
        dict[str, tuple[float, float, float]] | ndarray
    ),
    ch_names: list[str] | None = None,
) -> TRFData

    Attach source-space region centroids as channel info (see set_info).

    The source-space analogue of set_montage: for targets that are parcel or virtual-electrode timecourses rather than sensors, where a montage does not exist and MNE's own machinery has nothing to work with. The centroids are written into the channel positions of an mne.Info, so from here on the regions travel through the package exactly as sensors do -- mne.pick_info keeps them aligned when group.TRFGroup restricts a cohort to its common channels, and io.save stores them.

    What they unlock is the spatial adjacency of group.TRFGroup.tfce, which for parcels comes from statistics.source_adjacency (proximity) instead of a montage, and plots.TRFPlots.plot_source_butterfly. Topomaps stay unavailable: they need a head surface to interpolate onto, which region centroids are not.

    Parameters:

    Name Type Description Default
    positions (dict or array - like, shape(n_channels, 3))

    {region_name: (x, y, z)} or an array in the order of the target columns. Coordinates in metres, as MNE stores them (the frame only has to be consistent -- adjacency and colouring use relative distances). A dict is matched on the channel name, falling back to the name stripped of MNE's -0/-1 uniqueness suffixes, which appear whenever several centroids share a parcel name.

    		 required
    ch_names list of str

    Region names, in the order of the target columns. Defaults to the existing info's names, else target_names.

    		 None

    Returns:

    Type Description
    TRFData

    self, for chaining.
    See Also

    set_info : attach a ready-made mne.Info. statistics.source_adjacency : the graph these positions feed.

    Examples:

    >>> data = TRFData(features=feats, y=parcel_timecourses,
...                sample_rate=128)
>>> data.set_source_positions(label_positions, ch_names=label_names)

    Positions may also be added to targets ingested as an mne.Raw of region timecourses, which keeps that Raw's channel names and types:

    >>> data = TRFData(features=feats, y=raw_src, sample_rate=128)
>>> data.set_source_positions(label_positions)

    get_feature ¶

    get_feature(name: str) -> Tensor

    Materialize a base feature to a (n_total, n_subfeatures) tensor.

    Parameters:

    Name Type Description Default
    name str

    A key of the features dict this container was built with.

    		 required

    Returns:

    Type Description
    Tensor

    (n_total, n_subfeatures) on the container's device.

    Raises:

    Type Description
    KeyError

    If name is not one of the container's features.
    RuntimeError

    If the container has not been materialized yet.
    Notes

    Concatenates the segments with NaN buffers (segmented layout), moves the result to the device and caches it. The buffer depends on the crop window, so the cache is cleared whenever the container is re-materialized for a different one; within one window, repeated requests are free.

    create_partitions ¶

    create_partitions(
    n_folds: int | None = None,
    stratify_by_segment: bool | None = None,
    segments_as_folds: bool = False,
    train_size: float | None = None,
) -> TRFData

    Record the cross-validation partition config (lazy).

    This does not build the folds: the fold indices depend on the buffer-safe sample set, which is only known once a model fixes the crop window and triggers materialize. Here the cheap, values-free constraints are validated and the config stored; the folds are built at materialization, or immediately if the container is already materialized.

    Parameters:

    Name Type Description Default
    n_folds int or None

    The number of folds; None means DEFAULT_N_FOLDS (5). Ignored when segments_as_folds=True -- the fold count is then the number of segments, and a disagreeing value warns at materialization.

    		 None
    stratify_by_segment bool or None

    Block-stratified CV: within each segment, divide its sample positions into n_folds contiguous sub-blocks; fold k's test set is the union of sub-block k across all segments, so every fold sees every segment. None (the default) stratifies whenever the container is segmented and uses plain contiguous KFold otherwise; True requires the segmented layout; False always uses plain contiguous KFold. With a single segment it falls back to plain contiguous KFold.

    		 None
    segments_as_folds bool

    Leave-one-segment-out CV (the Lalor/mTRF paradigm). Fold s's test set is exactly segment s, so the fold count is the number of segments and n_folds is ignored. Requires the segmented layout with at least 2 segments. Takes precedence over stratify_by_segment.

    		 False
    train_size float

    A single contiguous train/test split: the first train_size fraction of the buffer-safe samples is the train fold, the rest the test fold, one fold in total. Used by the cv="train_test" paradigm; takes precedence over every other argument, which are then ignored.

    		 None

    Returns:

    Type Description
    TRFData

    self, for chaining.

    Raises:

    Type Description
    ValueError

    If train_size is not a fraction in (0, 1), or if a segment-based scheme is explicitly asked of a single recording.
    Notes

    Folds are always contiguous in time, with no sample-level shuffling: shuffling scatters near-in-time neighbours across train and test and, on autocorrelated signals like EEG, produces severe leakage. Use stratify_by_segment to balance segments without that contamination, or segments_as_folds for leave-one-segment-out CV.

    materialize ¶

    materialize(
    crop_lag_min: int,
    crop_lag_max: int,
    delay_margin: int = 0,
) -> TRFData

    Activate the lazy, window-dependent state for a given crop window.

    Parameters:

    Name Type Description Default
    crop_lag_min int

    The model's crop window in lags: the union of its default_window and its per-feature windows.

    		 required
    crop_lag_max int

    The model's crop window in lags: the union of its default_window and its per-feature windows.

    		 required
    delay_margin int

    delay_margin in samples.

    		 0

    Returns:

    Type Description
    TRFData

    self, for chaining.

    Raises:

    Type Description
    ValueError

    If crop_lag_max is below crop_lag_min.
    Notes

    Called by a model at construction. Builds the inter-segment NaN buffer layout, concatenates and moves the targets, derives the effective relevant_indexes (buffer-safe and not-bad) and builds the folds from the recorded partition config. Idempotent for a repeated (crop_lag_min, crop_lag_max, delay_margin); a different key recomputes everything and invalidates the feature cache.
