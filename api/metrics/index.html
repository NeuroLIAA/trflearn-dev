    Metrics¶

    The evaluation metrics and the registry that owns them: Pearson, R² and RMSE.

    metrics ¶

    metrics.py — Evaluation metrics for TRF models.

    Every metric the package can report lives here, registered by name in the :data:METRICS registry with the register decorator. Adding a metric is writing its functions and decorating them; nothing in models.py needs editing. Pearson, R² and RMSE ship with the package.

    Two functions per metric

    A metric is evaluated on two very different inputs, and the registry names both so the two paths cannot drift apart.

    fn(y_pred, y_true, sample_dim) is the direct computation. It reduces sample_dim and broadcasts the remaining dimensions right to left, so the gridsearch can score a whole regularization grid at once -- (n_values, n_samples, n_channels) against (n_samples, n_channels).

    from_sums(n, sum_x, sum_y, sum_x2, sum_y2, sum_xy) recovers the same value from sufficient statistics, which is what makes the block bootstrap affordable: bootstrap precomputes those five sums per block once and every resample is a sum over blocks, so the data is read once however many resamples are drawn. Arguments arrive as (batch, n_channels) tensors with n already broadcast to (batch, 1) and clamped to at least 1, so the body is plain elementwise algebra.

    from_sums is optional. Not every metric has a closed form in those five sums -- Spearman needs the ranks of the full resample, spectral metrics need the signal -- and leaving it None is what lets the bootstrap refuse a metric up front instead of silently reporting something else.

    bootstrap is that routine, and it lives here rather than on the model because nothing in it is about TRFs: it cuts two lists of held-out tensors into blocks, reduces each block once, and resamples the blocks. All it needs from a caller is where to put the tensors. The model keeps the one rule that is its own -- a block may not be coarser than a cross-validation fold -- and calls in here.

    Conventions

    The degenerate case belongs to the metric. A channel with no variance is undefined for Pearson and for R², both reporting 0 here, and perfectly well posed for RMSE -- which must not inherit that convention, since 0 is an error's best possible score and a flat channel would read as a perfect fit.

    higher_is_better is consumed only where the package chooses something -- the λ of _select_regularization, the fold of _aggregate_folds('max') -- through as_score. Everything stored, returned or plotted stays in native units: RMSE is always displayed as RMSE.

    Two things worth knowing before reporting these

    R² is not Pearson squared. On held-out data Pearson is invariant to any affine rescaling of the prediction and R² is not, so ridge shrinkage leaves r untouched while costing R² directly: R² sits below r² systematically, responds to regularization in a way r does not, and can select a different λ. Held-out R² can also be negative, so plots.plot_metric_topomap -- which defaults to a sequential colormap -- needs a diverging cmap for it.

    RMSE is in standardized target units, not microvolts: it is computed inside fit on the normalized targets, and the inverse transform only happens in predict. Under the default target_preprocess="Standardize" that keeps it comparable across channels and subjects, but it also makes it a near-monotone transform of R² (RMSE ~ sigma * sqrt(1 - R2)), so the two select nearly the same λ. RMSE earns its place when target_preprocess=None.

    DesignSums dataclass ¶

    DesignSums(
    n: int,
    gram: Tensor,
    cross: Tensor,
    column_sum: Tensor,
    target_sum: Tensor,
    target_sq_sum: Tensor,
)

    What scoring design @ coef takes from a design and its target.

    from_sums reads five sums of a prediction x and a target y. When x = X b, the three involving x are, channel by channel, s'b, b'Gb and b'h, with G = X'X, h = X'y and s the column sums of X. These sums, read once, score any number of coefficient matrices without forming a prediction.

    PredictionSums dataclass ¶

    PredictionSums(
    n: int,
    sum_x: Tensor,
    sum_y: Tensor,
    sum_x2: Tensor,
    sum_y2: Tensor,
    sum_xy: Tensor,
)

    The five sums from_sums reads, for several predictions at once.

    Every field but n is (n_coefs, n_channels): one row per coefficient matrix the prediction x = X b was formed with. Sums over disjoint rows add, so the folds of a cross-validation can be reduced one at a time and scored once, as if their predictions had been concatenated.

    pearson ¶

    pearson(
    y_pred: Tensor, y_true: Tensor, sample_dim: int = -2
) -> Tensor

    Channel-wise Pearson correlation between prediction and target.

    Parameters:

    Name Type Description Default
    y_pred Tensor

    Prediction, broadcastable against y_true.

    		 required
    y_true Tensor

    Target.

    		 required
    sample_dim int

    Dimension reduced over, the samples axis.

    		 -2

    Returns:

    Type Description
    Tensor

    Correlation with sample_dim removed; 0 where either side is flat.
    Notes

    Pearson is a ratio, so the divisor of the second moments cancels -- but only if it is the same on both sides. Writing the covariance over a and the deviations over b yields (b/a) * r. Here both are n (.mean() for the covariance, unbiased=False for the deviations), so the result matches np.corrcoef and scipy.stats.pearsonr exactly -- which is the point, since a TRF correlation is meant to be comparable with values from mTRF, MATLAB or R.

    Do not switch one side to unbiased=True: Bessel's correction unbiases a variance, not a correlation, and does nothing for the real downward bias of r towards rho. Applied to one side only it silently scales every reported metric by (n-1)/n.

    r2 ¶

    r2(
    y_pred: Tensor, y_true: Tensor, sample_dim: int = -2
) -> Tensor

    Coefficient of determination, 1 - SS_res / SS_tot.

    Parameters:

    Name Type Description Default
    y_pred Tensor

    Prediction, broadcastable against y_true.

    		 required
    y_true Tensor

    Target.

    		 required
    sample_dim int

    Dimension reduced over, the samples axis.

    		 -2

    Returns:

    Type Description
    Tensor

    R² with sample_dim removed; 0 where the target is constant.
    Notes

    SS_tot uses the mean of y_true over the samples being scored, so on held-out data this is the usual out-of-sample R² and can be negative: a model that predicts worse than the test set's own mean scores below 0. That is informative rather than a failure, and it is the difference from Pearson, which cannot see a mis-scaled prediction at all.

    		 -2

    Type Description
    Tensor

    Error with sample_dim removed.
    Notes

    The only lower-is-better metric registered here, and the reason higher_is_better exists at all. Deliberately without a zero-variance special case: a flat target is a well-posed input for an error, and forcing it to 0 -- pearson's convention for "undefined" -- would report a dead channel as a perfect fit.

    compute ¶

    compute(
    y_pred: Tensor,
    y_true: Tensor,
    metric: str = "Pearson",
    sample_dim: int = -2,
) -> Tensor

    Channel-wise metric values between a prediction and a target.

    Parameters:

    Name Type Description Default
    y_pred Tensor

    Prediction, (..., n_samples, n_channels).

    		 required
    y_true Tensor

    Target, the same shape or broadcastable against it.

    		 required
    metric str

    Any name, label or alias in the registry.

    		 'Pearson'
    sample_dim int

    The dimension holding samples, reduced over.

    		 -2

    Returns:

    Type Description
    Tensor

    The metric over the non-sample dimensions.

    Raises:

    Type Description
    ValueError

    If the two tensors disagree on the length of sample_dim.
    NotImplementedError

    If metric names nothing in the registry.
    Notes

    Only sample_dim has to match exactly; the remaining dimensions broadcast right to left, each pair matching or singleton. That is what lets the gridsearch score a whole regularization grid in one call. If y_pred is (n_values, n_channels, n_samples, n_channels) and y_true is (n_channels, n_samples, n_channels), the two will not broadcast unless y_true first gains a singleton.

    Each metric owns its handling of a zero-variance channel -- that answer is a property of the metric (0 for a correlation, a real error for RMSE), not of this function.

    block_sufficient_stats ¶

    block_sufficient_stats(
    y_pred_folds: list[Tensor],
    y_test_folds: list[Tensor],
    n_blocks: int,
    *,
    device: device,
    dtype: dtype
) -> dict[str, Tensor]

    Reduce held-out folds to per-block sufficient statistics.

    Parameters:

    Name Type Description Default
    y_pred_folds list of torch.Tensor

    Per-fold predictions, each (n_samples_fold, n_channels).

    		 required
    y_test_folds list of torch.Tensor

    Per-fold targets, matching those shapes.

    		 required
    n_blocks int

    Contiguous blocks to cut the concatenated folds into.

    		 required
    device device

    Where the reduced statistics are accumulated.

    		 required
    dtype dtype

    Precision the sums are taken in.

    		 required

    Returns:

    Type Description
    dict of str to torch.Tensor

    n_per_block of shape (n_blocks,) and sum_x, sum_y, sum_x2, sum_y2, sum_xy, each (n_blocks, n_channels). x is the prediction, y the target.
    Notes

    The folds are concatenated and cut into n_blocks contiguous blocks -- the last one absorbing the remainder, so no sample is discarded -- and each block is reduced to five sums plus its length. This is what makes the bootstrap affordable at all: the data is read once, here, and every resample afterwards is a sum over blocks, so the cost stops depending on how many resamples are asked for.

    sample_block_indices ¶

    sample_block_indices(
    n_blocks: int,
    n_resamples: int,
    random_state: int | None,
) -> ndarray

    Draw block indices with replacement, one row per resample.

    Parameters:

    Name Type Description Default
    n_blocks int

    How many blocks exist, and how many each resample draws.

    		 required
    n_resamples int

    How many resamples to draw.

    		 required
    random_state int or None

    Seed.

    		 required

    Returns:

    Type Description
    np.ndarray of shape (n_resamples, n_blocks)

    Block indices, with repetition.
    Notes

    This is the resampling scheme itself, kept on its own so it can be checked without running a fit. Each of the n_blocks positions in a resample is drawn uniformly and independently, so the block multiplicities of a resample are Multinomial(n_blocks, 1/n_blocks). That is what makes the resulting sample equally weighted, and therefore its percentiles bootstrap percentiles -- see bootstrap for why enumerating the distinct resamples instead does not.

    Drawing through NumPy rather than a torch generator keeps the same random_state producing the same indices on CPU and on GPU.

    bootstrap ¶

    bootstrap(
    y_pred_folds: list[Tensor],
    y_test_folds: list[Tensor],
    metric: str = "Pearson",
    n_blocks: int = 8,
    n_resamples: int = 10000,
    random_state: int | None = 42,
    *,
    device: device,
    dtype: dtype,
    verbose: int | None = None
) -> tuple[int, Tensor]

    Estimate a channel-wise bootstrap distribution by resampling blocks.

    Parameters:

    Name Type Description Default
    y_pred_folds list of torch.Tensor

    Per-fold predictions, each (n_samples_fold, n_channels).

    		 required
    y_test_folds list of torch.Tensor

    Per-fold targets, matching those shapes.

    		 required
    metric str

    Any name, label or alias in the registry. It must declare a from_sums form: this routine never revisits the data, it sums per-block sufficient statistics, and a metric without a closed form in those sums (Spearman, anything spectral) is rejected up front rather than approximated.

    		 'Pearson'
    n_blocks int

    Contiguous segments to split the data into before resampling. A caller holding a cross-validation split should keep this at or above its fold count, so that a block is never coarser than a fold.

    		 8
    n_resamples int

    How many resamples to draw. A few thousand already resolve a 95% percentile interval; raise it for narrower quantiles.

    		 10000
    random_state int or None

    Seed for the resampling. Fixed by default, so two runs of the same model report the same interval; pass a different value to see how much the interval owes to the resampling itself.

    		 42
    device device

    Where the statistics and the resamples are computed.

    		 required
    dtype dtype

    Precision the sums are taken in.

    		 required
    verbose int or None

    A resolved verbosity level overriding the global one. The progress bar over the resamples is shown at DEBUG only. See trflearn.verbosity.

    		 None

    Returns:

    Name Type Description
    n_resamples int

    Echoed back, so a caller can record what the interval rests on.
    distribution Tensor

    (n_resamples, n_channels), on the CPU.

    Raises:

    Type Description
    ValueError

    If n_blocks or n_resamples is not positive.
    NotImplementedError

    If metric declares no from_sums form.
    Notes

    The held-out predictions and targets are cut into n_blocks contiguous blocks, and n_resamples resamples are drawn -- each one n_blocks blocks sampled independently with replacement. Every resample is evaluated from precomputed per-block sufficient statistics, so the data is read once and the cost is linear in n_resamples, independent of how many folds produced it.

    This replaced an exhaustive enumeration of every combination-with-replacement of the blocks, and the change is not only about cost: the intervals it reports are narrower. Enumerating each distinct resample once weights them uniformly, while the bootstrap weights each by how many ordered draws produce it. The two measures differ most in the tails, which is where the percentiles are -- the degenerate resamples (every draw landing on the same block) are a large share of the uniform measure and a negligible share of the bootstrap one. The old intervals were therefore conservative rather than wrong in direction, but they were not bootstrap intervals. Sampling draws from the right measure and returns an equally weighted sample, which is also what lets every consumer keep taking plain percentiles and medians of distribution.
