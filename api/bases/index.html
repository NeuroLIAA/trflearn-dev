    Basis expansions¶

    feature_bases accepts any scikit-learn transformer, so this module exists for the two things scikit-learn does not provide: dropping a basis column, which a TRFlearn design needs and an ordinary regression does not, and expanding a sparse event feature at its events only.

    See Features & windows for why the drop is mandatory, which rule to pick, and why an event feature reverses the default.

    bases ¶

    bases.py — The spline basis, with the lab's convention pinned.

    models.TorchTRF accepts any scikit-learn transformer in feature_bases, and that mechanism needs nothing added to it. This module exists for the two things scikit-learn does not provide: dropping a basis column, which a TRFlearn design needs and an ordinary regression does not, and expanding an event feature at its events only::

    spline_basis(n_functions=4, order=3, knots="quantile", drop="mean")
spline_basis(scope="event")          # a sparse event amplitude
event_scoped(transformer)            # the same scope, for any basis

    A B-spline basis is a partition of unity: its columns sum to exactly 1 on every row it touches, and per-column standardization turns that into an exact linear dependency, repeated at every lag. Nothing crashes, because the ridge penalty covers a singular block, but regularization is then doing two jobs -- regularizing and keeping the block invertible -- so a tuned regularization is partly pricing an artificial redundancy that carries no information. Dropping costs nothing in expressiveness: the model has no intercept and the target is centered, so the remaining columns span the same space.

    An event feature -- a saccade's amplitude at its onset sample, zero everywhere else -- turns that around. Its zero means no event, not an event of amplitude 0, so scope="event" places the knots from the event rows and leaves every other row at zero, as unfold's spl() does. The columns then sum to the onset indicator instead of to 1: the full basis is well conditioned on its own, and dropping a column would remove the part of the response that does not depend on the amplitude, hence drop=None by default under this scope. Beside an onset regressor for the same event the full basis repeats it exactly, and drop="mean" becomes an identifiability requirement.

    A cohort -- TRFGroup or TRFMixedModel -- takes its bases already fitted and freezes them (freeze_bases), so that a spline column is the same function of the stimulus in every subject and its kernels can be averaged.

    The rest of the argument -- which column goes and why the evidence is not one-sided, the knot padding this module inherits from scikit-learn, and composing a basis with an elementwise transform -- lives in the Features & windows concepts page (docs/concepts/features.md), which the API page for this module links rather than repeats.

    Bases: BaseEstimator, TransformerMixin

    B-spline expansion that drops one column per input feature.

    Built by spline_basis, which is the documented entry point; this class is what it returns, and exists as a class so the object is picklable and inspectable (get_params) like any other scikit-learn transformer.

    It wraps SplineTransformer rather than subclassing it, because the drop index is a property of the data and not of the parameters: finding the column that peaks nearest a feature's mean needs the raw X at fit time, which a subclass's transform would no longer have.

    spline_basis ¶

    spline_basis(
    n_functions: int | None = None,
    order: int = 3,
    *,
    knots: str | ndarray = "quantile",
    drop: str | None = "auto",
    scope: str = "sample",
    extrapolation: str = "constant"
) -> SplineBasis

    A B-spline basis expansion with one column dropped per input feature.

    The convention this package recommends, in one call. See the module docstring for why the drop is mandatory, why the default is "mean", and why an event feature reverses both.

    Parameters:

    Name Type Description Default
    n_functions int or None

    How many columns each input feature is expanded into -- after the drop. This is the number that reaches the design: the block's n_subfeatures, the second axis of coef_, and the count of plot labels. The underlying spline space is one larger whenever a column is dropped, and the helper works n_knots out backwards from it. None (the default) keeps the spline space at five functions whatever the drop -- 4 columns with one dropped, 5 without -- which at the default order is the lab's reference function (3 knots, cubic).

    		 None
    order int

    Polynomial order of the splines: 3 is cubic, 4 quartic, 1 piecewise linear. Passed to scikit-learn as degree.

    		 3
    knots (quantile, uniform)

    Where the interior knots go. "quantile" places them at quantiles of the stimulus, so resolution follows where the data actually is -- the right default for the skewed amplitude distributions this is usually applied to. "uniform" spaces them evenly over the observed range. An array places them by hand, as SplineTransformer expects.

    		 "quantile"
    drop (auto, mean, last)

    Which column to remove per input feature. "mean" is unfold's rule (the column peaking nearest that feature's mean), "last" matches scikit-learn's include_bias=False. None keeps the whole basis, which leaves a per-sample block exactly singular under per-column standardization -- available on purpose, but not a neutral choice there. "auto" (the default) is "mean" under scope="sample" and None under scope="event"; pass "mean" when an onset regressor for the same event is in the model.

    		 "auto"
    scope (sample, event)

    Which rows the basis is fitted on and applied to. "sample" expands every row, zeros included -- right for a continuous feature, where 0 is a value (silence, in an envelope). "event" is for a sparse feature whose 0 means no event: the knots come from the rows where any column is non-zero, those rows are expanded, and every other row stays exactly zero.

    		 "sample"
    extrapolation str

    What transform does outside the fitted range, passed through to SplineTransformer. Relevant to predict on new stimulus.

    		 'constant'

    Returns:

    Type Description
    SplineBasis

    A transformer with fit/transform, usable directly as a feature_bases value and picklable, so save(with_bases=True) carries it.

    Raises:

    Type Description
    ValueError

    If drop or scope is not a known value, or n_functions is too small for order -- the smallest spline space of a given order has order + 1 functions, so asking for fewer is a contradiction rather than a rounding matter, and it says so rather than quietly giving you something else.

    Examples:

    A continuous feature:

    >>> model = TRFModel(
...     TRFDataset=data, features=["envelope"],
...     default_window=(-0.1, 0.4),
...     feature_bases={"envelope": spline_basis(n_functions=4)},
... )

    A saccade's amplitude beside its onset, unfold's 1 + spl(amplitude):

    >>> model = TRFModel(
...     TRFDataset=data, features=["saccade", "sac_amplitude"],
...     default_window=(-0.2, 0.4),
...     feature_bases={
...         "sac_amplitude": spline_basis(scope="event", drop="mean")
...     },
... )

    event_scoped ¶

    event_scoped(transformer: Any) -> EventScoped

    Any basis expansion, applied at the events of a sparse feature only.

    What spline_basis(scope="event") does, for any other transformer: it is fitted on the rows where the feature is non-zero, applied to those rows, and every other row stays exactly zero.

    Parameters:

    Name Type Description Default
    transformer sklearn-style transformer

    Anything with fit/transform, pipelines included. It is cloned at fit, so the object passed in stays unfitted.

    		 required

    Returns:

    Type Description
    EventScoped

    A transformer usable directly as a feature_bases value.
    Notes

    The wrapper goes outermost: it reads the events off the raw stimulus, so nothing inside it ever sees a zero. That makes np.log safe on an amplitude, where per sample it would map every empty row to -inf.

    Examples:

    >>> feature_bases = {"sac_amplitude": event_scoped(make_pipeline(
...     FunctionTransformer(np.log), spline_basis(drop=None)
... ))}

    basis_fingerprint ¶

    basis_fingerprint(basis: Any) -> str | None

    A digest of a basis's fitted state, equal for bases that transform alike.

    Parameters:

    Name Type Description Default
    basis (transformer, _FrozenBasis or None)

    A fitted scikit-learn-style transformer, possibly frozen.

    		 required

    Returns:

    Type Description
    str or None

    The SHA-256 of the pickled transformer, so two transformers fitted separately on the same values share it, and a transformer read back from a file keeps it. A transformer that cannot be pickled (one holding a lambda) is identified by object instead, and only matches itself. None without a basis.
    Notes

    The bytes hashed are those of a copy that has been through one pickle round trip already. scikit-learn estimators, and scipy's BSpline from 1.18 on, do not pickle to the same bytes before and after a round trip, but they do from the first one on.
