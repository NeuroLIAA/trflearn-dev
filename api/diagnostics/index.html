    Diagnostics¶

    What a fitted design says about itself: how well conditioned it is, how much its feature blocks overlap, and what the fit costs in effective parameters. Mixed into every paradigm, so these are methods of the model you already have.

    None of it is computed by fitting — see diagnostics for why — and all of it is cached, so a model loaded from disk reports the numbers its file carried without recomputing anything.

    ModelDiagnosticsMixin ¶

    The design report of models.TorchTRF, kept out of the estimator itself.

    Mixed into models.TorchTRF beside plots.ModelPlots, on the same reasoning: reporting on a fit is not fitting, and the class is easier to read when the two are not interleaved.

    Every *_ attribute below reads the cache and, on a miss, computes it through the method that owns it -- diagnostics for the first five, information_criteria for the last three. All eight are None for solver="cross_corr", which has no penalized normal system.

    It holds no state of its own. What it needs from the host:

    _diagnostics The cache every value is stored in and read from. _fitted_regularization Refused when None: there is no regularized design to report on. _require_data and _full_design_pass The full-design assembly, and the guard that explains how to get the data back when a model was loaded without it. _build_block_penalty, _coef_matrix, _trim_blocks and _feature_column_slices The design's own geometry, which the criteria and the per-block GVIF are computed against.

    Participation ratio of the unregularized design.

    diagnostics ¶

    diagnostics(
    *,
    vif: bool = True,
    criteria: bool = False,
    recompute: bool = False
) -> dict

    Compute the numerical diagnostics of the design, once, and cache them.

    Diagnostics are a report on the fit, not a product of it: nothing here runs during fit/gridsearchCV. The reason is cost. The numbers are defined on the full design -- the normal matrix over every relevant sample, not a single fold -- so that they are single, well defined quantities that do not depend on an arbitrary fold and are identical for the pooled and averaged paradigms. Assembling it is a whole extra pass over the data, on top of the ones the fit already made fold by fold and discarded, and it was being paid by every fit whether or not anyone ever read the result. Asked for explicitly, it is paid once, by whoever wants the answer.

    The cache is keyed by name, and a stored None counts as computed: with solver="cross_corr" there is no penalized normal matrix, so all five are legitimately None and asking again would not help.

    Parameters:

    Name Type Description Default
    vif bool

    Compute the collinearity report: vif_, vif_columns_ and vif_aliased_, which come out of one decomposition and are therefore cached together. This is the one extra (n_columns, n_columns) eigendecomposition on top of the two the condition number needs; vif=False skips it and leaves the keys uncomputed, so a later read of any of the three can still fill them in.

    		 True
    criteria bool

    Also fill the information criteria (see information_criteria) from the same assembly. They are a different report, and asking for them separately is a second identical pass over the design -- which is nothing on one model and one pass per subject on a cohort. This method is the one entry point for "walk the full design once", and vif / criteria say what to compute while it is in memory; information_criteria remains the direct entry when the criteria are all that is wanted.

    		 False
    recompute bool

    Recompute even if the values are cached. Only useful after something about the design changed, and impossible on a model loaded without its data.

    		 False

    Returns:

    Type Description
    dict

    {"condition_number": float | None, "effective_rank": float | None, "vif": ndarray | None, "vif_columns": ndarray | None, "vif_aliased": ndarray | None}. The three vif keys are absent when vif=False and they had not been computed before, and the criteria keys are present only with criteria=True.

    Warns:

    Type Description
    UserWarning

    When the condition number exceeds ILL_CONDITIONED_ABOVE. This is the one thing fitting used to say on its own; it now waits until someone asks.
    UserWarning

    When the design carries exactly aliased columns, naming both how many take part in a dependency and how many are redundant. Only with vif=True, which is the default.

    Raises:

    Type Description
    RuntimeError

    If the model has not been fitted, or if it was loaded without its data and the values are not already cached from the file.

    information_criteria ¶

    information_criteria(
    *, recompute: bool = False
) -> CriteriaReport

    AIC and BIC of the fitted model, computed once and cached.

    What they are for: the metrics in metrics say how well this model predicts, and cannot rank two different models, since adding a feature block almost never makes the fit worse. AIC and BIC put the fit and a price for complexity in one number, so they can. Lower is better for both. To compare, use selection.compare, which also refuses the pairs that are not comparable.

    Parameters:

    Name Type Description Default
    recompute bool

    Recompute even if cached. Same meaning and same limits as in diagnostics.

    		 False

    Returns:

    Type Description
    CriteriaReport

    The nine keys, their shapes and when they are None, are on that class.

    target_ss is y'y of the raw target over the rows that entered the fit, and it is what selection.compare fingerprints to refuse two models that are not describing the same response. Raw and not standardized on purpose: with the default target_preprocess="Standardize" the standardized y'y is approximately n for any recording whatsoever, so it would pass two entirely different datasets as the same one.

    Raises:

    Type Description
    RuntimeError

    If the model has not been fitted, or was loaded without its data and the values are not already cached from the file.
    Notes

    Computed like the rest of the design report -- on demand, on the full relevant design at the fitted regularization, assembled in float64 -- and cached in the same store, so diagnostics() and this share a pass' worth of discipline but not the pass itself.

    The three ingredients.

    The likelihood is in-sample. That is the definition, not an oversight: AIC exists because the in-sample fit is optimistic, and the penalty is the correction. See trflearn.selection for why penalizing a held-out likelihood would count that correction twice.

    The complexity is the effective degrees of freedom, the trace of the ridge hat matrix H = X (X'X + n a M)^-1 X', computed here as tr((XTX + a M)^-1 XTX) on the per-sample-averaged normal matrix -- which is already the right quantity, since the package solves (X'X/n + a M), i.e. (X'X + n a M), so the n cancels. It runs from n_columns at λ -> 0 down to 0 as λ grows. The column count would be wrong: a penalized fit does not spend n_columns parameters, and counting columns would make two models with the same windows equally complex however differently they were regularized.

    The residual sum of squares is read off the same normal matrices, N * (y'y - 2 b'X'y + b'X'X b), so scoring the fit costs no second pass over the design and no prediction.

    Two widths, on purpose.

    With delay_margin > 0 the margin lags are estimated and then trimmed away. The residuals are those of the reported filter, so rss uses the trimmed design and coef_; the effective degrees of freedom describe the estimation that produced it, so edf is computed at fit width -- those parameters were fitted from the data and did spend its information, whatever happened to them afterwards. At the default delay_margin=0 the two widths are the same and the distinction is moot.
