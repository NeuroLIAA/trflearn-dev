    Saving and loading¶

    save / load for fitted models and cohorts, and the limitations of a saved file.

    io ¶

    io.py — Saving and loading fitted models and cohorts.

    Two verbs. A model or a cohort writes itself with save, and load brings it back, deciding what it is from the file's own manifest::

    model.save("s01.pkl")
group.save("cohort.pkl")
lmm.save("mixed.pkl")

model = trflearn.load("s01.pkl")                  # predicts new stimulus
model = trflearn.load("s01.pkl", TRFDataset=data) # + refit and predict()
group = trflearn.load("cohort.pkl")               # a fully live cohort
lmm = trflearn.load("mixed.pkl")                  # fitted, and refittable
    What is in the file

    A model saves its fitted state, not its data. The live object holds the container, the targets and every block's raw stimulus, so pickling it would write the whole dataset to disk once per subject. What predict actually reads is kilobytes: the kernels, each block's predict-time normalizer statistics, the block metadata (spec, sub-feature count, delays) and the bases. That -- plus the metric, the diagnostics and the cross-validation figure's ingredients -- is what the file carries.

    A cohort saves everything it has. TRFGroup already discards each model after fitting and keeps only compact arrays, so there is no fitted state to restore: a reloaded cohort does everything a live one does, including fitting more subjects. Its per-subject bootstrap distributions and cluster-test results travel with it: both are expensive to recompute, and the second is what shades the figures. (A model has no bootstrap to save -- fit(bootstrap=True) returns the distribution rather than storing it; the cohort is what keeps it.)

    A mixed model saves its sums and its search. mixed.TRFMixedModel keeps every subject's sufficient statistics and nothing else of the recordings, so the file carries them whole, with the settings, the channel info and the variance-parameter search of the last fit (mixed.optimize.ParameterFit). Every other estimate is read off the likelihood at that optimum on load, without searching again, so a loaded model tests, plots, refits and takes more subjects like the one that was saved.

    The format

    A pickle of a plain dictionary -- nested dicts, strings, numbers and NumPy arrays, and nothing else. Pickling the live objects would embed this package's class paths, so any later rename would break every file already written; a payload with no class in it survives refactors, and load rebuilds the object from it. The file is called .pkl because that is what it is: no private extension is invented, and dispatch reads the manifest rather than the suffix, which stops being true as soon as someone renames the file.

    format_version is written into every file, and anything but the current version is refused outright rather than half-read.

    Within a version, keys are added but never removed or repurposed. The version is bumped only for a change that would make an old file unreadable -- version 2 renamed a block descriptor's key -- because a bump orphans every file already on disk, while a new key orphans nothing: a reader that does not find it has lost only what did not exist when the file was written. A payload of the current version is therefore a lower bound on what it holds, and every key added since the last bump is read with .get and treated as "never computed" when absent. Removing or repurposing a key is what the version number is for.

    Keys outlive renames. A key keeps the name it was first written under even when what it stores is renamed in the code: _STORED_AS maps the two, and save and load translate through it. The regularization was called alpha when the format was set, so the files still say alpha and every file written before the rename keeps loading.

    Limitations

    Worth knowing before relying on a saved file:

    • A pickle executes code when it is read. Only load files whose origin you trust. This is a property of the format, not of this package.
    • A loaded model has no data. predict(X_new), every plot including validation_plot(), to_evoked and all the reported numbers work. Calling fit, gridsearchCV or predict() with no arguments raises and tells you to reload with TRFDataset=, which re-materializes the container and gives you a fully live model again.
    • A loaded cohort has no limitations. It aggregates, tests, plots and keeps fitting subjects.
    • Diagnostics travel as a frozen report. condition_number_, effective_rank_, vif_, vif_columns_, vif_aliased_ and the information criteria (aic_, bic_, edf_ and the rest of TorchTRF.information_criteria) are saved as they stood, and a loaded model reports those numbers without recomputing anything. Whatever had not been computed at save time -- they are on demand, see TorchTRF.diagnostics -- is saved as None and reads back as None, on a live model too. Reload with TRFDataset= and call diagnostics(recompute=True) to get them.
    • with_bases=True files are tied to library versions. Bases are sklearn transformers, the one part of the state that is not an array. By default they are not embedded: the payload records what each block had, and load asks for them, so the file stays pure data. Embedding them is one flag away and couples the file to the sklearn and Python versions that wrote it.
    • The MNE info is rebuilt, not preserved. Channel names, types, sampling rate and sensor positions are stored and reassembled on load -- enough for topomaps, to_evoked and the cluster test's adjacency; the rest of the Info is dropped. Storing the object itself would put an MNE class in the payload and make mne -- an optional dependency here -- mandatory to open the file. If mne is missing at load time the file still opens, with a warning, and everything except montage-dependent plotting works.

    save ¶

    save(
    obj: TorchTRF | TRFGroup | TRFMixedModel,
    path: str | PathLike,
    *,
    with_bases: bool = False
) -> None

    Write a fitted model or a cohort to path.

    Parameters:

    Name Type Description Default
    obj TorchTRF subclass, TRFGroup or TRFMixedModel

    The object to serialize. A model must be fitted: one with no coef_ has nothing to save. A mixed model is saved fitted or not.

    		 required
    path str or PathLike

    Destination file. Parent directories are created. .pkl is the convention, but the path is used verbatim -- load reads the manifest, not the suffix.

    		 required
    with_bases bool

    Embed the feature_bases transformers in the file. Off by default so the payload stays pure data; see the module's Limitations.

    		 False

    Raises:

    Type Description
    RuntimeError

    If a model carries no fitted kernel.
    TypeError

    If obj is a model of a paradigm load could not rebuild.

    load ¶

    load(
    path: str | PathLike,
    *,
    TRFDataset: TRFData | None = None,
    feature_bases: dict | None = None
) -> TorchTRF | TRFGroup | TRFMixedModel

    Read back a model or a cohort written by save.

    Parameters:

    Name Type Description Default
    path str or PathLike

    The file to read. What it contains is decided by its manifest.

    		 required
    TRFDataset TRFData

    Models only. Given a container, the model is rebuilt against it and comes back fully live -- able to refit and to predict() on its own stimulus. Without it the model predicts on new stimulus and reports, but cannot refit.

    		 None
    feature_bases dict

    Models only. {spec: transformer} for a model whose blocks used bases and that was saved with with_bases=False. Ignored when the file already carries them.

    		 None

    Returns:

    Type Description
    TorchTRF subclass, TRFGroup or TRFMixedModel

    Whichever the file's manifest says it holds.

    Raises:

    Type Description
    ValueError

    If the file is not a TRFlearn payload, is in another format version, needs a basis that was neither saved nor passed, or is a cohort given the model-only arguments.

    Warns:

    Type Description
    UserWarning

    If the file carries channel info and mne is not installed, or if a cohort's bases were described rather than embedded.
