    Features, interactions & windows¶

    When building a model, features is a list of specs:

    • a string selects a base feature by name;
    • a tuple ("k1", "k2") is an interaction — the outer product of the raw features (d1·d2 columns).

    Per-feature delay windows¶

    The model always takes a default_window=(tmin, tmax) (seconds) — the fallback for any feature without its own window. Each feature can override it with feature_windows={spec: (tmin, tmax)} (for an interaction, the union of its constituents' windows). Windows are independent — a feature window may extend beyond default_window — and the container's crop window is their union, so no subset rule applies. Keys must name a selected feature: an unknown key (a typo, or a feature you did not select) raises KeyError rather than being ignored.

    model = TRFModel(
    TRFDataset=data,
    features=["envelope", "spectrogram", ("envelope", "spectrogram")],
    default_window=(-0.2, 0.6),
    feature_windows={"envelope": (-0.1, 0.4)},
    solver="ridge-laplacian",
)

    Basis expansions (feature_bases)¶

    To model a nonlinearity in the stimulus, attach a basis expansion to a feature's amplitude via feature_bases={spec: transformer} — keyed exactly like feature_windows. The transformer is any scikit-learn-style object with fit/transform (canonically SplineTransformer): each raw column (n_samples, n_subfeatures) is mapped to (n_samples, n_subfeatures·k) before lagging, so a scalar feature becomes k smooth basis channels.

    For splines, use spline_basis, which pins the recommended convention in one call:

    from trflearn import spline_basis

model = TRFModel(
    TRFDataset=data,
    features=["envelope"],
    feature_bases={"envelope": spline_basis(n_functions=4, order=3,
                                            knots="quantile", drop="mean")},
)

    n_functions is the number of columns the design actually receives — the block's n_subfeatures, the second axis of coef_, the count of plot labels — after the dropped column. Left out, it keeps the spline space at five functions whatever the drop — 4 columns with one dropped, 5 without — which at the default order is the lab's reference function (3 knots, cubic). order is the polynomial order (3 cubic, 4 quartic), knots is "quantile" (resolution follows where the data is — the right default for skewed amplitudes), "uniform", or an explicit array.

    Why a column is dropped¶

    A whole B-spline basis makes the block exactly singular

    B-splines are a partition of unity: the k basis columns sum to 1 in every row, and feature_preprocess centres each column, so the centred columns sum to zero — an exact linear dependency, repeated at every lag. Nothing raises, because the ridge penalty covers the deficiency, but regularization is then holding the block together as well as regularizing it, and the tuned value is chosen partly to fix an artificial redundancy that carries no information. Measured on one spline block: condition number 1.6e+07 against 3.3e+04 for the same design with a column removed.

    The collinearity report catches it, but the other two diagnostics do not, so read the right one. condition_number is computed on the regularized matrix and cannot tell the two apart at a working regularization; effective_rank is a participation ratio, not a rank, and does not see exact singularity. What does see it is vif_columns_, which reads inf for every column of the block, and vif_aliased_, which lists them — with a UserWarning naming the count and the rank deficit, which are far apart here: every column takes part in the dependency while only one per lag is redundant. The block's vif_ stays unremarkable on purpose: the redundancy is inside the block, and the generalized VIF measures what a block shares with the others.

    Dropping the column costs nothing. The model has no intercept and the target is centred, so the remaining k-1 columns span exactly the same space — this is the same reason unfold and other event-based toolboxes remove one spline from a basis that accompanies an intercept.

    Which one, and how many. drop="mean" removes the column peaking nearest the predictor's mean (unfold's rule, the default); drop="last" matches sklearn's include_bias=False; drop=None keeps the whole basis. This is a documented choice, not an obvious one: with ridge and no intercept the two rules are different models rather than reparametrizations, and the evidence points both ways — conditioning strongly favours "mean" (VIF 2.5 against 195 on a skewed stimulus), while one synthetic test scored marginally better with "last". Conditioning is the reproducible half, which is why it wins the default.

    The drop is per input feature, not one column overall. sklearn lays the expansion out feature-major and the partition of unity holds within each feature's group, so a feature with several columns (a spectrogram, an interaction) loses one column per group. Removing a single one overall would leave every other group's dependency standing.

    Event features: scope="event"¶

    A sparse event feature — a saccade's amplitude at its onset sample, zero everywhere else — needs the basis applied at the events only. Its zero means no saccade, not a saccade of amplitude 0, and a per-sample expansion gets both halves wrong: the quantile knots are placed from a column that is mostly zeros, so they pile up at 0 and leave the amplitudes in a single polynomial piece; and a spline evaluated at 0 is not 0, so every empty sample enters the design as a small event.

    feature_bases={"sac_amplitude": spline_basis(scope="event")}

    fits the knots on the rows where the feature is non-zero, expands those rows and leaves every other row at exactly zero — what spl() means in unfold. A row counts as an event when any of its columns is non-zero, the same test drop_zero_rows applies. For any other transformer, event_scoped does the same, and goes outermost: nothing inside it ever sees a zero, so even np.log is safe on an amplitude.

    from trflearn import event_scoped

feature_bases={"sac_amplitude": event_scoped(make_pipeline(
    FunctionTransformer(np.log), spline_basis(drop=None)))}

    The drop turns around. At the events the columns sum to 1, elsewhere to 0: their sum is the onset indicator, which centring does not cancel. So the whole basis is well conditioned on its own, and it needs every column, because the part of the response that does not depend on the amplitude — the average response to a saccade — lives in that sum. With one column dropped the block can no longer represent it, and that part of the response is forced into shapes that vary with the amplitude. Hence drop=None is the default under this scope, and the two ways of writing the same model are:

    Model features feature_bases["sac_amplitude"] Columns
    Amplitude alone ["sac_amplitude"] spline_basis(scope="event") 5
    Onset + amplitude (unfold's 1 + spl(a)) ["saccade", "sac_amplitude"] spline_basis(scope="event", drop="mean") 1 + 4

    They span the same space. Beside an onset regressor for the same event — a feature of ones at the event samples — the whole basis would repeat it exactly, so there the drop is an identifiability requirement and has to be asked for. Pick the second form when the onset kernel is wanted as a term of its own, as in unfold.

    Composition: log, and anything else¶

    feature_bases takes any transformer, so an elementwise transform and its composition with a basis need nothing new:

    from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import FunctionTransformer
import numpy as np

feature_bases={"sac_amplitude": make_pipeline(FunctionTransformer(np.log1p),
                                              spline_basis(n_functions=4))}

    Use log1p, not log: with rectified envelopes zero is frequent and np.log maps it to -inf without complaining. And a lambda is not picklable, so it would fail at save(with_bases=True) rather than at fit time — wrap a named function.

    Two things to know¶

    The basis is fit once on the relevant stimulus samples (knots come from the stimulus, never the response — no target leakage) and reused across folds and in predict. The expanded n_subfeatures flows through coef_, the diagnostics and to_evoked unchanged (a feature with more than one column exports one Evoked per basis channel).

    Fitting once means the quantile knots see the held-out folds. The leak is mild — the basis never sees the target — but it is why spline_basis defaults to sklearn's knot padding with extrapolation="constant" rather than the unfold-exact clamped construction. In range the two span the same space (measured maximum principal angle ~1e-13); outside it, clamped boundary functions have nothing to continue into and evaluation raises. So if the basis is ever tightened to per-fold fitting, held-out stimulus beyond the training range becomes reachable during the grid search, and only the sklearn padding survives it. Choosing it now is what keeps that door open.

    drop_zero_rows is unaffected by any of this: it reads its mask from the pre-basis stimulus, because informativeness is a property of the stimulus rather than of how it was parametrized — and a per-sample basis maps 0 to something non-zero.

    In a cohort¶

    A cohort averages each basis column across subjects, which only means something if column k is the same function of the stimulus in every subject. Refitted per subject it is not: quantile knots follow each subject's own amplitudes, so the same column peaks at a small saccade in one subject and at a larger one in the next. So TRFGroup takes its bases already fitted and never refits them. Fit each one once, on a stimulus that covers the whole cohort:

    amplitudes = np.concatenate([features["sac_amplitude"]
                             for features, _ in cohort.values()])
group = TRFGroup(
    features=["saccade", "sac_amplitude"],
    default_window=(-0.2, 0.4),
    feature_bases={"sac_amplitude": spline_basis(scope="event", drop="mean")
                   .fit(amplitudes)},
)

    An unfitted basis is refused when the cohort is built, and a subject whose bases differ from those the cohort was fitted with is refused at fit_subject — after reloading a cohort saved without its bases, set group.feature_bases back to the same fitted ones.

    delay_margin¶

    An optional margin (seconds) added on each side of every feature's window to absorb ridge edge effects; it is trimmed off the kernel before predicting.
