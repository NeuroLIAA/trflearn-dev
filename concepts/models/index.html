    Models & paradigms¶

    TRFModel(...) is a single entry point; the cv argument picks the cross-validation paradigm and returns the matching backend instance.

    cv Backend Paradigm
    "pooled" (default) PooledTRF Standard k-fold: for each test fold, one model is fit on the pooled complement and predicts the held-out set.
    "averaged" AveragedTRF Crosse–Lalor: one model per partition; fold j is predicted by the leave-one-out average of the others.
    "train_test" TrainTestTRF A single contiguous train/test split; the λ that scores best on the test fold is kept. 
    model = TRFModel(TRFDataset=data, features=[...])                  # pooled (default)
model = TRFModel(TRFDataset=data, features=[...], cv="averaged")   # Crosse–Lalor
model = TRFModel(TRFDataset=data, features=[...], cv="train_test", # 80/20 split
                 train_size=0.8)

    All paradigms share the same features / interactions / windows / bases, solvers and diagnostics.

    Fitting¶

    • gridsearchCV(regularization_grid, ...) selects a single λ by cross-validation (an inner train/validation split), then — with run_fit=True — refits at that λ. With no regularization_grid it searches np.logspace(-3, 3, 13); it chooses on R² unless metric says otherwise, and the refit reports the same metric (see Recommendations for when Pearson is the better choice). Aggregation across folds defaults to "mean" in every paradigm, so the λ they select is comparable across them ("median" — more robust to an outlier fold — "max" or a fold index are one argument away); metric_limit_percentage biases toward a larger λ, which shrinks the kernels without improving their shape (see Recommendations). It records a validation figure (see validation_plot).
    • fit(regularization, ...) fits at a fixed λ and stores coef_ and the predict-time normalizers.
    • predict(X_new=None) applies coef_ to a stimulus (the model's own by default, or a dict{name: array} of base features), returning the response in target units.

    Scoring on a subset of samples¶

    The held-out metric covers every sample of each fold. A sparse model — word onsets, fixations, with no continuous feature beside them — predicts the mean wherever its design row is all zero, and those stretches still enter the correlation. Its r then answers how much of the recording the model explains, which is the honest default. It does not answer the event-locked question, how well the response is predicted given that an event occurred. score_on, on fit and gridsearchCV, restricts the held-out samples the metric is computed on:

    score_on= scores on
    None (default) every sample
    "informative" samples where any block has an event within its delay window
    ["onsets"] the same, for the named blocks only — beside a continuous feature every sample is informative, so this is the form to use there
    {"onsets": (0.0, 0.5)} 0 to 0.5 s after each event, a window of its own inside the model's delay range
    boolean array / callable exactly those samples, one entry per real sample (as for relevant_indexes); a callable receives the held-out samples' numbers

    An event is a sample where the raw feature, before any basis, is non-zero. The window of the dict form may belong to a feature the model does not fit, so two models can be scored on the same samples — an envelope model and an onset model both on {"onsets": (0.0, 0.5)}:

    model.gridsearchCV(grid, score_on={"onsets": (0.0, 0.5)})
model.metric_name_    # "R² (onsets 0 to 0.5 s)"
model.scored_on_      # {"score_on": {"onsets": (0.0, 0.5)}, "fraction": 0.31}
    • Only the scoring changes. The estimation and predict are untouched, and drop_zero_rows stays independent: it decides which rows fit the kernels, score_on which ones score them, and together they fit and score on the event windows.
    • Every metric of the call sees the same samples — per fold, concatenated and bootstrapped, in all three paradigms. In gridsearchCV that includes the metric that selects λ, so λ is tuned for the question the reported metric answers; pass it there, not in run_fit_kwargs.
    • The result says what it is. A Pearson over a subset is not comparable to one over every sample, nor to a literature value, so metric_name_ is marked and scored_on_ keeps the selection and the fraction of held-out samples it kept. Both are saved with the model.

    Diagnostics¶

    diagnostics() returns condition_number_ (of the regularized normal system), effective_rank_ (participation ratio of the design) and a three-part collinearity report. All of them are computed on the full relevant design at the fitted λ, so they are single, well-defined values — identical across the two cv paradigms.

    attribute what it answers
    vif_ per block: how much of it is explained by the other blocks, as the generalized VIF of Fox & Monette (1992), GVIF^(1/2d). 1.0 means nothing shared
    vif_columns_ per column, the textbook VIF; inf where the column is an exact combination of the others
    vif_aliased_ which columns take part in a linear dependency — the actionable one

    vif_ is per block rather than per column because a lagged design is collinear within a block by construction: contiguous lags of an autocorrelated signal are correlated, that is not a defect, and any per-column average reports it as one — large for every block, separating nothing. The generalized VIF is invariant to how a block is parametrized internally, which is exactly what removes lag collinearity from the answer. A block with no other block to share with (a single-feature design, or one wholly redundant given the rest) reads nan.

    Read vif_ next to vif_aliased_ rather than on its own. The block number is computed on a full-rank subset of the columns, so one aliased column cannot zero a determinant and take the whole report with it — which also means an exact dependency does not inflate it: two duplicated blocks read 1.0 each once the duplicates are set aside. The per-column half is what catches those.

    They are not computed by fitting. Assembling the full design is an extra pass over the data — in float64, because an exact dependency is not distinguishable from a merely collinear direction at float32 — and a diagnostic is a report on the model rather than a part of it, so it is computed when asked for and cached:

    model.diagnostics()              # everything
model.diagnostics(vif=False)     # skip the (n_columns, n_columns) decomposition
model.condition_number_          # computes on first access, then reads the cache

    Two UserWarnings come with them, on the first read rather than at the end of every fit: the 1e6 ill-conditioning one, and one naming both the number of aliased columns and the rank deficit when the design carries an exact dependency.

    A cohort records them per subject under TRFGroup(..., diagnostics=True) (off by default — it is one extra pass per subject). The record keeps the per-block vif keyed by spec and n_aliased, the count; group.summary() then carries a "diagnostics" entry with the spread across subjects, which is what says whose design is the odd one out.

    Comparing two models: AIC and BIC¶

    A held-out metric says how well one model predicts. It cannot rank two different models — envelope alone against envelope + onsets — because adding a feature block almost never makes the fit worse, and with ridge it is not even obvious how many parameters were added. information_criteria() puts the fit and a price for complexity in one number, and compare() ranks a set of them. Lower is better for both criteria.

    model.information_criteria()   # {"aic", "bic", "edf", "n", "rss", ...} per channel
model.aic_, model.bic_, model.edf_          # on demand, then cached

table = trflearn.compare({"envelope": m1, "envelope + onsets": m2})
table.best["bic"]                           # by the summed criterion
table.best_per_channel["aic"]               # (n_channels,) of names — topoplottable
table.delta_bic_total                       # {name: ΔBIC against the winner}
print(table.summary())                      # one printable row per model

    Three things decide the number, and each is a deliberate choice:

    • The likelihood is in-sample, on the full design at the fitted λ. That is the definition rather than an oversight of the package's held-out discipline: AIC exists because the in-sample fit is optimistic and the penalty is the correction. Penalizing a held-out likelihood would apply that correction twice.
    • The complexity is the effective degrees of freedom tr(H), not the column count. A penalized fit does not spend n_columns parameters — edf_ runs from n_columns at λ → 0 down to 0 as λ grows — and counting columns would make two models with the same windows equally complex however differently they were regularized.
    • The channels add up. Each criterion is (n_channels,), and the total is their sum, which is the multivariate criterion under independent channels — the assumption the rest of the package already makes.

    compare() refuses models that are not comparable rather than differencing them anyway: different n (one of them with drop_zero_rows), a different channel count, or a different y'y over the fitted rows — the fingerprint that catches a different target or a different target_preprocess. A criterion is an absolute number attached to one dataset, and nothing in the arithmetic notices when the dataset changed. solver="cross_corr" has no penalized system and therefore no tr(H): all of them are None there, and compare() says so.

    Two limits

    EEG residuals are autocorrelated. Both criteria assume independent samples; continuous EEG is nowhere near that, so the effective sample size is a fraction of the row count and both are overconfident — they call a difference decisive sooner than the data warrant. BIC suffers less, since its penalty grows with log(n). Use them to rank models fitted on the same data, not as a significance test.

    λ was chosen by cross-validation, and this is an in-sample criterion, so the data does double duty, mildly.

    Across a cohort the same comparison is TRFGroup.compare_to, which pairs subjects by id and turns each one's criteria into a single observation — and that framing escapes the autocorrelation warning above, since it does not depend on the sample size inside a subject. It needs TRFGroup(..., criteria=True), decided before fitting.

    The train_test paradigm¶

    The simplest option: a single contiguous split whose "CV" just sweeps the grid, fits on train and keeps the λ that scores best on the test fold. The split is set by train_size (on the model, or via create_partitions(train_size=...); defaults to 0.8).

    It is optimistic

    There is no inner validation and no fold aggregation: λ is chosen on the very set whose metric is then reported, so the reported metric is the maximum over the grid, not an unbiased estimate. Use it for a quick, straightforward look; prefer pooled / averaged when the number must be trustworthy.

    averaged caveat

    The leave-one-out average is itself clean — a fold's coefficients never see its own data — but each partition is standardized once with its own statistics, a mild feature-scale leakage into the CV estimate (no target leakage). pooled avoids this by standardizing the test fold with training statistics.
