    Group analysis — TRFGroup¶

    TRFGroup declares a model spec once, without data, then fits it per subject in a loop, keeping only the minimal per-subject results (kernels, held-out metric, selected λ, an optional bootstrap distribution) and discarding each full model — so a large cohort stays memory-light.

    import numpy as np
from trflearn import TRFData, TRFGroup

group = TRFGroup(
    features=["envelope", "spectrogram"],
    default_window=(-0.2, 0.6),        # same knobs as TRFModel
    cv="pooled",
    solver="ridge-laplacian",
    regularization_grid=np.logspace(-3, 6, 20),
    regularization_strategy="mean-curve",       # one λ for every subject
)


def load(subject_id):
    features, eeg = cohort[subject_id]
    data = TRFData(features=features, y=eeg, sample_rate=128)
    data.create_partitions()           # 5 folds, stratified by segment
    return data


for subject_id in cohort:              # 1. each subject's validation curve
    group.search_subject(load(subject_id), subject_id)
group.share_regularization()                    # 2. the best λ of the mean curve
for subject_id in cohort:              # 3. every subject at that λ
    group.fit_subject(load(subject_id), subject_id)

group.summary()                        # cohort size + descriptive stats
ga = group.grand_average()             # {spec: {"mean","std","sem","n"}}

    The kernels it averages, tests and draws are in original units, the recording's unit per unit of each feature. Why both choices matter when subjects are compared is in One λ for every subject and Kernel units.

    Cluster permutation tests¶

    group.permutation_test(spec) tests that a feature's kernel departs from zero across the cohort while controlling the family-wise error over the whole grid. It wraps mne.stats.spatio_temporal_cluster_1samp_test and builds the full adjacency (delay — and, for a multi-column feature, sub-feature — lattices × channel adjacency) from the montage kept in TRFData.info, so the cohort's targets must be MNE Raw.

    threshold picks the flavour:

    from trflearn.statistics import t_threshold

# Threshold-free cluster enhancement (the default): a per-point p-value, no
# cluster-forming threshold to guess.
t_obs, pvals = group.permutation_test("envelope")
t_obs, pvals = group.tfce("envelope")               # the same thing, named

# Cluster mass at a fixed cluster-forming t: one p-value per cluster, shared by
# every point in it.
thr = t_threshold(0.01, df=len(group) - 1)
t_obs, pvals = group.permutation_test("envelope", threshold=thr)

    Cluster inference does not localize

    Under cluster mass the p-value belongs to the cluster, not to a delay or a channel. The honest statement is "this cluster is significant"; reading a latency off its edges is not supported by the test. TFCE gives a genuine per-point p-value instead.

    t_obs, pvals = group.tfce("envelope")      # (n_delays, n_channels)
t_obs, pvals = group.tfce("spectrogram")   # (n_delays, n_subfeatures, n_channels) — kept

    A scalar feature returns maps of shape (n_delays, n_channels); a multi-column feature keeps its sub-features natively — nothing is averaged away. Results are cached in group.stats_[spec].

    Comparing two cohorts¶

    The permutation tests above ask whether a kernel differs. A different question is which model spec describes the cohort better — envelope alone against envelope + onsets — and no held-out metric answers it, because adding a feature block almost never makes the fit worse. compare_to ranks the two by AIC and BIC, which price the complexity:

    lean = TRFGroup(["envelope"], (-0.1, 0.4), criteria=True)
rich = TRFGroup(["envelope", "onsets"], (-0.1, 0.4), criteria=True)
for sid, data in subjects.items():        # the same subjects into both
    lean.fit_subject(data, sid)
    rich.fit_subject(data, sid)

table = lean.compare_to(rich)           # a CohortComparison
print(table.summary())                  # both criteria, one row each

table.best["bic"]                       # 'self' or 'other'
table.n_favouring_self["bic"]           # how many subjects prefer `lean`
table.wilcoxon["bic"]                   # (statistic, p) across subjects
table.delta_bic_per_channel             # (n_channels,) — for a topomap

    criteria=True is not optional and has to be decided before fitting: the cohort keeps arrays and discards each subject's model, so the criteria cannot be recovered afterwards without refitting. With diagnostics=True also on, both reports come out of one pass over each subject's design instead of two.

    The sign is the opposite of the contrasts above

    The difference is self - other and lower is better for both criteria, so a positive delta favours other. In permutation_test_contrast, a positive t_obs favours self. The two methods sit next to each other and disagree because the underlying quantities do.

    Two aggregations, both reported¶

    Each subject contributes one number — their criterion summed over channels — and what to do with that (n_subjects,) vector is a modelling choice, so both answers are given rather than one chosen quietly:

    reading keys what it assumes
    random effects .median, .n_favouring_self, .wilcoxon each subject is one observation; an unusual subject shows up in the vector instead of dragging the answer
    fixed effects .total the cohort as one large model with per-subject parameters; dominated by whoever contributed the most data

    When the two disagree, that is the finding. It is the signature of an atypical subject, and reporting only the one that agrees with you is what this return value is shaped to prevent.

    The Wilcoxon signed-rank test is the honest statistic here, and for a specific reason: the per-subject criteria are overconfident, because both assume independent samples and EEG residuals are autocorrelated — but that inflation is within a subject. Whether N independent subjects fell on the same side does not inherit it. Signed-rank rather than a t-test because one badly conditioned design produces an outlier of arbitrary size, which a rank test ignores. Below six subjects the test cannot reach p < 0.05 at any effect size, so it returns nan with a warning instead of a number nobody should quote.

    compare_to refuses a comparison it cannot interpret: cohorts with different subjects, a cohort fitted without criteria=True, or any subject whose two fits do not describe the same response (different row count, channel count, or raw y'y). A criterion is an absolute number attached to one dataset, and nothing in the arithmetic notices when the dataset changed.

    Plotting a cohort¶

    The group uses the shared plotting API:

    group.plot_features()                             # one summary column per feature
group.plot_average("envelope", show_stats=True)   # green/red significance shading
group.plot_joint("envelope")                      # grand-average Evoked passthrough
group.plot_metric_topomap()                       # grand-average metric
group("s01").plot_average("envelope")             # a single subject's view

    Reading a subject's numbers¶

    group(subject_id) gives the plots; group.results(subject_id) gives the numbers that were stored when that subject was fitted:

    res = group.results("s01")
res["regularization"]                       # the λ actually fitted (searched or fixed)
res["metric"]                      # held-out metric, (n_channels,)
res["scored_on"]                   # {"score_on", "fraction"}, None if every sample
res["coef_"]["envelope"]   # fold-averaged kernel, in kernel_units,
                           # (n_channels, n_subfeatures, n_delays)
res["scales"]                      # {"target", "features"}: what the
                                   # standardization divided by
res["delays"]["envelope"]          # its lags, in samples
res["bootstrap"]                   # {"n_samples", "distribution", "random_state"} or None
res["condition_number"], res["effective_rank"]   # None unless diagnostics=True
res["vif"]["envelope"]             # that block's generalized VIF, 1.0 = nothing
                                   # shared with the other blocks
res["n_aliased"]                   # design columns that are exact combinations
                                   # of the others; 0 for a healthy design
res["aic"], res["bic"]             # channel-wise, None unless criteria=True
res["edf"]                         # effective degrees of freedom of the fit
res["n"], res["target_ss"]         # which data those criteria describe

group.subjects                     # the same view for the whole cohort
"s01" in group, len(group)         # membership / cohort size

    The four diagnostics follow the cohort's diagnostics=True, off by default because it costs a full extra pass over each subject's design, and they are None otherwise.

    Read vif and n_aliased together. The GVIF is computed on a full-rank subset of the columns, so that one aliased column cannot zero a determinant and take the whole report with it — which means an exact dependency is reported by n_aliased, not by a large GVIF. Two duplicated blocks read 1.0 each once the duplicate columns have been set aside: n_aliased is the one that catches them.

    Read one subject at a time they cannot say much — the question a cohort asks is whether this subject's design is the odd one out, so group.summary()["diagnostics"] carries the spread of each block's GVIF across subjects and names the subjects whose design has aliased columns:

    design = group.summary()["diagnostics"]
design["gvif"]["envelope"]["max"]  # the worst subject for that block
design["aliased_subjects"]         # {subject_id: n_aliased}, empty if none

    The per-column arrays (vif_columns_, vif_aliased_) stay on the model: they are one entry per design column, which does not belong in a per-subject record. Refit the odd subject on its own to inspect them.

    Both are read-only mappings: assigning into them raises TypeError, so a stray line in a notebook cannot corrupt the cohort behind grand_average() or permutation_test(). The arrays inside are the stored ones rather than copies, so .copy() before modifying one in place. The kernels are the exception in original units, which are computed on each call.

    Choosing how subjects are fitted¶

    The fitting strategy is part of the spec, declared once on the group. cv picks the paradigm ("pooled", "averaged", "train_test"), fit_method picks whether λ is searched or fixed, and the remaining parameters of the underlying TRFModel fit are accepted as keywords:

    group = TRFGroup(
    features=["envelope"],
    default_window=(-0.2, 0.6),
    cv="train_test", train_size=0.8,      # backend-specific knobs included
    regularization_grid=np.logspace(-3, 6, 20),
    metric_limit_percentage=0.05,         # prefer the smoothest λ within 5%
    bootstrap=True,
)

# ... or skip the search entirely:
group = TRFGroup(features=["envelope"], default_window=(-0.2, 0.6),
                 fit_method="fit", regularization=1e3)

    Every one of those is a default that fit_subject can override per subject, and it also takes any other keyword the chosen paradigm's fit / gridsearchCV accepts — keywords belonging to fit are routed into the refit stage automatically:

    group.fit_subject(data, "s07", metric="mse", per_fold_metric=True)
group.fit_subject(data, "s08", fit_method="fit", regularization=50.0)

    A keyword the selected cv does not support raises TypeError listing the ones it does (e.g. inner_train_cutoff exists only for cv="pooled"). A subject fitted with fit_method="fit" ignores the group's search-only defaults (inner_train_cutoff, metric_aggregation_function, metric_limit_percentage), so a group set up for the search can still fit one subject at a known λ. Pass fit keywords such as bootstrap directly; fit_subject does not take run_fit_kwargs.

    score_on restricts the samples every subject's metric is computed on (see Scoring on a subset of samples). On the group it must be one of the declarative forms — "informative", a list of features or a {feature: (tmin, tmax)} window — since those mean the same thing for every recording; a boolean array or a callable belongs to one subject's fit_subject. The cohort's figures label the metric with it, and each record keeps scored_on:

    group = TRFGroup(features=["onsets"], default_window=(-0.2, 0.6),
                 regularization_grid=np.logspace(-3, 6, 20),
                 score_on={"onsets": (0.0, 0.5)})
group.fit_subject(data, "s09", score_on=artifact_free)   # a mask of its own

    One λ for every subject¶

    A subject's best λ grows with its noise, and a larger λ shrinks the kernel more. Fitted each at its own λ, a noisier subject comes out smaller for the same response, so a comparison between subjects or groups partly measures their noise. One λ for a whole group has the derivation and the simulations. regularization_strategy decides:

    regularization_strategy What fit_subject does
    "mean-curve" fits at shared_regularization_, the best λ of the subjects' mean validation curve
    "median" fits at the geometric median of the λs the subjects chose on their own
    "leave-one-out" fits at the λ where the other subjects' average kernel best predicts each subject (below)
    "subject" searches and fits each subject at its own λ, in one loop
    unset (None) as "subject", and warns once when the subjects' λs differ

    The two shared strategies need every subject's curve before any final fit, and the cohort keeps no data, so they take two passes over the subjects: search_subject runs a subject's search and keeps its curve (n_values floats), share_regularization() picks the λ, and fit_subject fits each subject at it. Called before share_regularization(), fit_subject raises with that loop in the message. A banded search shares the whole λ vector, scale and ratio, and metric_limit_percentage applies to the mean curve as it would to one subject's. Following the two passes without naming a strategy shares by "mean-curve".

    search_subject takes the same overrides as fit_subject that configure the search (inner_train_cutoff, score_on, validation_plot, ...), but not regularization_grid or metric: averaged curves have to share one grid and one metric. A cohort fitted at one fixed λ (fit_method="fit") already shares it and needs neither.

    regularization_search_ shows what the choice was made from: the λ values searched, each subject's curve, the λ each subject's own search chose, the strategy, and the curve the shared λ was selected on.

    search = group.regularization_search_
search["curves"]["s01"]        # (n_values,), one subject's validation curve
search["chosen"]["s01"]        # the λ that subject would have taken alone
search["cohort_curve"]         # the mean curve, or the leave-one-out one

    One pass¶

    The two passes load every subject twice. keep_kernels_by_regularization=True makes it one: search_subject also fits the subject at every λ of the grid and keeps those kernels, and share_regularization() fills every subject's record at the shared λ. The compute is the same; the records are the ones fit_subject would store.

    group = TRFGroup(
    features=["envelope"], default_window=(-0.2, 0.6),
    regularization_grid=np.logspace(-3, 6, 20),
    regularization_strategy="mean-curve",
    keep_kernels_by_regularization=True,
    n_subjects=len(cohort),
)
for subject_id in cohort:
    group.search_subject(load(subject_id), subject_id)
group.share_regularization()           # every subject is now fitted

    The cost is memory, n_values × n_channels × n_columns numbers per subject, where n_columns counts every feature's sub-features times its lags. Nothing is written to disk. The size is exact before the first fit: it is printed at INFO, and past half of the memory available search_subject raises MemoryError before fitting, projected over n_subjects when it is given and over the subjects searched so far when it is not.

    Spec (float32, 20 λ) Per subject 30 subjects 30, leave-one-out
    64 channels, 2 features × 65 lags 0.6 MB 19 MB 22 MB
    64 channels, 52 features × 77 lags 20 MB 590 MB 2.4 GB

    kernels_by_regularization(subject_id) returns them, in the cohort's kernel_units: entry i of each kernel is what fit_subject would store at the i-th λ, and the metric at every λ comes with them. A saved cohort does not carry them.

    With bootstrap, diagnostics or criteria, a record needs the subject's data, so share_regularization() only chooses the λ and the loop of fit_subject stays.

    Leave-one-subject-out¶

    regularization_strategy="leave-one-out" chooses the λ at which the average kernel of the other subjects best predicts each subject: at every λ, each subject's recording is predicted from the others' mean kernel and scored with the cohort's metric, and the curve averages that over channels and subjects. It is the question the grand average is for — how well a kernel estimated without a subject describes them. In the inner benchmark it came closest to the best λ in hindsight for a strong predictor in heavy noise, where the mean curve over-regularizes.

    It needs every subject's kernels at every λ, so it keeps them on its own, in the same single pass. It also keeps the sums of each subject's design, X'X and X'y, to score a subject after their data is gone: n_columns² more numbers per subject, whatever the channels and the grid, which is what makes wide designs expensive (the last column above). The kernels are averaged in the cohort's kernel_units, over common_channels.

    Kernel units¶

    Standardize divides each subject's recording by its own standard deviation, which contains its noise, so in standardized units a noisier subject's kernel is smaller even at one λ. kernel_units="original", the default, undoes it: every kernel the cohort hands out — results, subjects, grand_average, the cluster tests, the contrasts and the figures — is multiplied by \(\sigma_y / \sigma_x\) from that subject's training data. That is the same fitted model written in the recording's units per unit of each feature, so λ keeps its meaning. kernel_units="standardized" gives the coefficients as fitted, which the figures label \(\sigma_y/\sigma_x\).

    The setting can change after fitting: group.kernel_units = "standardized". The grand average follows, and cluster tests run in the other units are cleared, with a warning, since they no longer describe what the figures show. A paired contrast refuses two cohorts in different units. A cohort saved before the scales were recorded can only be read in standardized units; asking it for original ones raises and says so.

    See the API and the pure helpers in trflearn.statistics (grand_average, descriptive_summary, cluster_1samp, t_threshold).
